# Dao2 試玩回饋整理

先鎖定版本（預設版或 `?edition=econ-r1`）、存檔出處、境界與目標。依 `AGENTS.md` 選驗證範圍。真實桌面 Web 使用 Chrome 和隔離存檔。含 Era2 時，讀 Roadmap 的 EARLY-FLOW1 及其連結的現行試玩計畫。

保留玩家原話、當時畫面與實際操作。逐個卡點記錄：起始狀態、預期下一步、玩家實際所做、結果與證據。分開記找路／操作時間、可同時做事的等待、沒有有效下一步的等待。加速模擬與已有路線知識的代理操作另標，避免將它們當成人類首次體驗。

從最早卡住的點開始，優先做一個可區分根因的對照：

- **介面／引導**：保留相同狀態與規則，只補一句目前缺什麼、在哪做、做完回哪。若因此能繼續，檢查入口、文案、返回及進度回饋。
- **數值節奏**：路徑已懂且可操作，記正式報價、可用庫存及權威產率／工作時間。找出扣除可並行活動後的空等，分清缺料、在途、滿倉及工位等待。
- **系統設計**：路徑已懂且材料或時間寬裕時，仍有缺乏選擇的重複交接、序列閘門或同時揭露太多義務。列清真正必要的前置、可選支線，以及降低價格仍會留下的步驟。
- **實作缺陷**：畫面狀態與正式規則不符、命令失效或重載丟失狀態時，先保留最短重現步驟與實際結果。渲染卡頓另留效能觀測，和找路／等資源分開。

輸出每個卡點的主因候選、共因、信心與下一項最小驗證。可用「待驗」保留假設。若沒有試玩紀錄，只交付試玩步驟及靜態假設。調整方案回到相同檢查點重測，一輪只改一類變因，並標記使用的 fixture 與真實玩家紀錄。

流程參考 [Claude Code Game Studios 的 playtest-report](https://github.com/Donchitos/Claude-Code-Game-Studios/blob/main/.claude/skills/playtest-report/SKILL.md)。
