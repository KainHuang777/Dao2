# 侍女／仙侍系統與大型角色插圖提案

日期：2026-10-31。任務 `MAID-DESIGN`，狀態 **PROPOSED／待使用者選定**。本文件是 v2 新方案，不代表已實作或已接受美術方向。使用者本輪要求優先於舊 Roadmap：回應 itch.io 玩家對畫面吸引力與女性角色不足的反饋，先提案。

## 1. 建議方向

以「具名女性角色＋職掌委任＋羈絆章節＋大型插圖」建立可持續擴充的仙侍系統。入口可稱「仙侍」，角色身分仍有侍女、劍侍、丹師等差異，避免全員只是換衣服的同一種功能。

首位角色在練氣前段、茅屋落成後相遇；目標是正常新手前 3–5 分鐘內看見角色與第一張大圖，實際時間需以新手流程驗證。不能等金丹才開始呈現核心賣點。已有進度玩家由一次性書信承接，不重跑新手或覆寫進度。

本輪推薦適度養成方案，不直接擴成完整戀愛／結婚／生育系統：

| 方案 | 內容 | 取捨 |
| --- | --- | --- |
| A：角色美術更新 | 立繪、情境台詞、初遇圖 | 最快看到視覺變化，但後續互動薄弱 |
| **B：仙侍系統（推薦）** | A＋明確職掌、可控委任、羈絆章節、回憶圖鑑 | 同時改善畫面與人物存在感；首版可收斂為一位 |
| C：完整道侶玩法 | B＋戀愛分支、伴侶選擇、婚契與複雜人物關係 | 敘事、保存與內容量顯著擴大，另立後續大型任務 |

## 3. 玩家循環

相遇 → 一次共同委託 → 入府／開啟職掌 → 共同經歷里程碑 → 羈絆章節 → 專屬大圖與人物變化。

- **相遇**：用一張大圖與簡短對話建立性格；首位不抽卡、不以稀有材料擋住登場。
- **職掌**：每位有一項可理解的協助；先提供預覽，玩家指定後才執行。
- **羈絆**：四階候選「初識／相知／信任／同道」。主要由共同事件及一次性里程碑推進，有限贈禮只作補充；沒有每日打卡或離線掉好感。
- **章節**：每位完整版本三章，至少一個有態度差異的選擇。先以穩定章節旗標記錄選擇，不做大量結局分叉；不以單次答錯永久失去角色或大圖。
- **回憶**：已讀劇情與已解鎖插圖可重看；跳過演出不影響規則結果。插圖由同一份角色設計衍生，成長透過表情、服裝細節與場景呈現。

人物台詞要回應「已發生的事」，例如首次突破、指定工作完成、前世約定，不能把未做的事寫成共同記憶。離線回來只整理真實工作紀錄，不憑台詞贈送資源。

## 5. 委任功能的邊界

DAO2 已有持續製造，仙侍新增價值是「替玩家記住有界目標及保留額」，現有手動／持續操作維持原資格。首版青蘅僅一個指定配方、一個目標、一組原料保留額，不做通用 AI 代理或全生產鏈自動排程。

- 委任由玩家明確啟用，可暫停／解除，顯示下一步和預估成本；同一產線以現有工作所有權防止委任與持續製造重複開工。
- 不得跌破各原料保留額。按既有批次產量計算可做批數；若一批會超出目標，停止並解釋，不偷改每批產量。
- 不自動突破、轉世、花道心道證、領取一次性選擇或變更航線政策；容量不足、前置不滿、壽盡、保存待重試均依正式規則停下。
- 首版不新增常駐產出乘區。角色差異先由便利與故事建立，避免新系統推翻宗門／天賦剛完成的平衡。
- 一次只啟用一位職掌；看圖、重播和偏愛展示與工作資格分開，換展示角色不偷換工作。
- 線上、離線、分段推進與輪迴邊界須一致；多角色多職掌並行待後續明確設計，不先做空殼。

## 6. 大圖如何真正進入畫面

角色不能只藏在深層圖鑑，也不能只剩世界上一個看不清的小人。

| 場景 | 建議呈現 | 目的 |
| --- | --- | --- |
| 初遇 | 場景 CG＋短對話與兩個可理解選擇；首位早期必定可遇見 | 新玩家立即認識人物 |
| 洞府侍立 | 可選、可收合的當值角色半身展示；與原 HUD／建築／鏡頭安全區共同排版 | 日常能看見喜愛角色，產生可辨識截圖 |
| 仙侍頁 | 寬式約 40–50% 留給主立繪，另側為人物介紹／職掌／羈絆；比例是候選，不是固定像素契約 | 大圖成為主體且操作清楚 |
| 羈絆章節 | 場景大圖、獨立文字層、固定跳過／繼續與關閉；通關後收入回憶 | 給解鎖大圖明確期待 |
| 洞府世界 | 美術通過後少量人物小像與站位；不強制每位都擺在島上 | 保留活世界感 |
| itch 展示素材 | 接入後以實際遊戲畫面製作角色頁、初遇與洞府截圖；封面另構圖 | 讓入口呈現本作的新視覺賣點 |

MAID-UI-1已依2026-11-01使用者接入要求，先以無玩法命令的敘事「人物」頁歸屬現有「遊歷」，見[正式狀態](development-status.md#maid-ui-1)。下列經營職掌歸屬仍為未核定系統候選，不另建重複入口。

仙侍功能的原提案優先置於現有「經營」群組，洞府角色點擊走同一 canonical route；不增加第五個主入口。羈絆／回憶在同一功能頁內，分頁、固定 CloseSeal、字型、44px 命中沿現有共用元件。短橫式將立繪縮為可點預覽，另開看圖；文字和操作仍留在有界容器內，不縮字或裁掉臉部。

本案尚未獲核定，這些布局是候選，不覆蓋 docs/19 的現行規範。洞府半身展示若無安全空間，先以可開合人物區處理，不能遮住突破、保存恢復或核心世界目標。

2026-11-01 使用者要求先實作「洞府侍立」可收合展示；實作範圍與安全區見 [docs/49 §13](49-maid-companion-system-design.md)。展示偏好已於同日以 `state.maid.version = 2` 的 `display` 欄跨存檔／輪迴保存，見 [docs/49 §15](49-maid-companion-system-design.md)。

## 7. 美術方向與首版產量

推薦「精緻仙俠女性立繪＋工筆山水環境」：面部與眼神清楚、髮型／剪影有辨識度，絲綢、薄紗、腰身與姿態帶出女性魅力；人物比現有遠景更明亮清晰，保留青玉、古金與暖燈色系。性感程度可調，但角色氣質與臉部辨識先成立。此為原創設計方向，不指定抄用其他作品的角色。

先比較同一人物的三種方向：偏工筆仙氣／精緻日系仙俠／較成熟華麗。推薦以第二種為角色可讀性起點，保留第一種的材質與環境；最後由使用者看樣張選擇，不能把文字推薦當美術接受。

**一位完整角色的資產包**：

1. 一張人物設定基準：正面／側面、衣飾、髮色、瞳色與配色；先確認臉和造型。
2. 一套透明全身主立繪，四個表情以局部差分處理，避免重畫四個不同的人。
3. 兩張橫式場景 CG：初遇＋羈絆終章（燈下候歸）；中間章用主立繪及現有場景承接。
4. 一組頭像與半身展示衍生裁切；一個世界小像只在確定世界站位且有需要時追加。
5. 初版以靜態圖、淡入與少量既有特效呈現，骨架／Live2D 動畫後續再評估。

原稿可採直式約 2048×3072、橫式約 2560×1440，僅作製作目標；runtime 根據實際顯示尺寸導出。主角、背景、前景光效分層，文字／數值／選項由 Godot 畫，圖片本身不含 UI。臉、手與敘事物件留安全構圖區，短式另設取景，不把原圖硬拉寬。

每張圖保留生成提示詞、原檔、角色參照、用途、切層、衍生關係與來源／授權狀態；人工核對同角一致性、手部、衣飾、alpha 邊緣與遊戲內效果後才標 accepted。首次只載當前需要的圖，不一次預載所有 CG；後續角色擴充再按現有 Godot 資產管線評估，不預建新下載平台。

## 8. 輪迴、保存與現有系統接合

建議以「靈契與記憶跨世」交代具名仙侍延續，不讓同一位普通凡人無限存活卻不說明。

- 跨世保留：已結識／結契、羈絆章節、選擇、解鎖插圖、已領一次性章節獎勵與展示偏好。
- 當世重置：工作執行、在途角色任務（若未來新增）、臨時效果。委任模板可保留，但新世預設暫停，玩家確認且配方／設施／資源資格滿足後才恢復。
- 已結契角色新世不再重付招募費；用短重逢台詞承接，不重播首次獎勵。世末可有角色送別，但不攔截轉世操作。
- 接既有章節／事件與回憶呈現能力，角色狀態由純規則維護；UI 只送命令和讀 View。美術切換、動畫、重播不能給收益或重抽結果。
- 引入角色狀態時需版本化 schema／content／rules 與空狀態遷移；舊存檔載入不隨意贈關係或改庫存。使用既有候選保存、拒寫恢復、重試與命令去重，素材載入錯誤不可破壞角色資料。
- 不把侍女變成宗門 token 的新兌換品，也不與靈獸共用持有槽／餵養或好感貨幣。
