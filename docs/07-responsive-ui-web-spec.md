## 1. 決策與邊界

遊戲畫面由 Godot 場景繪製。Web 匯出只將該場景放入瀏覽器的 `<canvas>`，HTML/JavaScript 只處理啟動、下載、瀏覽器生命週期和平台橋接。正式世界、HUD、抽屜、彈窗、命中與相機輸入都必須在 Godot 的 `Node2D`、`Camera2D`、`CanvasLayer` 與 `Control` 中完成。

`1280×720` 是洞府橫式構圖、鏡頭初始範圍與美術製作的基準，不能當作 Web 版固定可視尺寸。一般 Web 匯出使用隨瀏覽器可用區域調整的畫布，不能以固定畫布、強制瀏覽器捲軸或裁切內容來迴避窄螢幕版面問題。Web export 的 Canvas Resize Policy 維持 Adaptive；除非另有已核准的嵌入式展示需求，不設為 None。

Godot 專案設定和實作須維持以下原則：

| 項目 | 規則 | 用意 |
| --- | --- | --- |
| 設計基準 | viewport `1280×720` | 保持洞府美術及桌面鏡頭的共同構圖基準 |
| 2D 縮放 | `stretch/mode = canvas_items` | 依實際畫布重新繪製 2D 世界與 UI，保留文字清晰度 |
| 長寬比 | 明確設定 `stretch/aspect = expand` | 不拉伸美術；較寬或較高畫布呈現額外場景空間 |
| Web 畫布 | Adaptive resize | 瀏覽器改變視窗、方向或可視高度時，Godot 收到新的可視區域 |
| 高 DPI | 可限制世界渲染倍率；關鍵 UI 仍以可讀字級呈現 | 不以降低 UI 清晰度換取效能 |

`canvas_items` 與 `expand` 的配置依 Godot 多解析度建議；Web 畫布可隨瀏覽器調整。[Godot 多解析度文件](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html) [Godot Web 匯出文件](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)

## 2. 場景與介面責任

世界層採 `Node2D`、獨立建築、人物、特效與 `Camera2D`。它可以因畫布比例增加可見山河，但不得把 UI 文字、按鈕或面板烘焙到背景圖中。

HUD 由 `CanvasLayer` 下的一個全畫面根 `Control` 管理；根節點使用完整矩形錨點和容器，不以每個子元件的絕對像素 `position` 組成版面。元件只可在容器內使用少量視覺微調偏移。視窗大小或方向變動後，版面管理器必須在同一幀重新套用對應版型。

介面分成四個互不重疊的責任區：

| 區域 | 內容 | 行為規則 |
| --- | --- | --- |
| `TopStatus` | 境界、修煉、壽元、目前目標入口 | 兩模式保持固定位置；直式按可視高度收斂目標 |
| `ResourcePanel`／`ActionSlot` | 左側三態資源清單；獨立採集動作 | 關閉／數量／完整；已解鎖資源全部可在面板內捲動，滿倉變色；採集鈕明示動詞與目標 |
| `WorldViewport` | 洞府、建築命中、相機與狀態特效 | 必須保有可拖曳與可點選的安全操作區 |
| `BottomNavigation` | 洞府／經營／修行／遊歷 | 固定四入口；群組內分頁互斥，設定與工具歸齒輪 |
| `ManagementRail`／`ModalHost` | 右側營造簿、獨立捲動的建築列表、同欄詳情，以及存檔、九界等暫態畫面 | 建築列可直接建造／升級，列主體只展開資訊；詳情需明確再開 |

面板不得長期遮住正在選取的建築或唯一必要的下一步。若詳情開啟會遮住目標，場景應把鏡頭平移至可見位置，或改用不遮擋該目標的抽屜方向。非彈窗 UI 不得互相覆蓋；彈窗只可覆蓋其下層，並有明確的關閉動作。

### 資源與建築的容量規則

- 空島模式保留修行 HUD、左側資源三態與目標引導；引氣／手動採集位於獨立動作槽。資源讀數不可直接送採集命令。完整系統引導按需展開，沒有獨立「資源總覽」面板。
- 管理模式保留同一修行 HUD 與左側資源面板，桌面／橫式在右側顯示營造簿，欄寬不超過 400 邏輯像素；直式使用可視寬度。營造簿依高度顯示目標與分類，建築列表獨立捲動。過短的直式管理頁可暫收動作槽，切回空島即可採集。
- 建築列常態只顯示名稱／等級、需求進度條、直接建造／升級鈕；點列主體才展開同欄效果與成本；明確的「詳情」鈕開完整內容，在原欄替換列表，返回保留捲動位置。數值與成本從 ViewModel 讀取。
- 常駐底部導航為洞府／經營／修行／遊歷。九界與輪迴等玩法使用群組分頁，不能放進 More。低特效、存檔管理、說明與演出重溫歸齒輪；輪迴資格與待決機緣保留主入口提示。頁面頂部分頁與返回列固定，內容可捲動；同時只開一個玩法頁面。
- 狀態面板的實際最小高度須參與排版；縮放控制位於面板下方並留間距。短橫式畫面沒有安全高度時，縮放控制可暫時隱藏，仍須保留拖曳／滾輪／雙指縮放及返回洞府途徑。詳細面板與底部導航不得被左上面板覆蓋。
- 2026-09-20 AGY 截圖否決了「十座地塊排在單一浮島」的做法：島面沒有對應的空地與路徑，抽象加號和名稱牌會浮在草地／崖壁上。M2 現行方案由 Godot「營造設施」清單管理多數生產與倉儲建築，島上只保留有明確地景承托的茅屋。清單和島上物件讀同一建築 ID 與 ViewModel、送同一命令。
- 新地標只有在獨立建築圖、建前地基、透視與尺寸、選取區、各版型遮擋均經驗收後才能加入島面；未建的普通設施不得在世界留加號／文字牌。後續 Era 不自動增加世界地塊；專門城區與自由布置的前置條件、存檔邊界見 [建築呈現與修行境界擴充規格](08-building-presentation-and-era-expansion.md)。

## 3. 版型狀態

版型由 Godot 可視區域的有效寬度和長寬比決定；Web 驗收以瀏覽器 CSS viewport 作外部證據。實作可集中在一個版面管理器或 `GameShell`，不能把斷點判斷分散在各功能控制器。

| 版型 | 進入條件 | 必須呈現的排列 |
| --- | --- | --- |
| 寬式 | 有效寬度至少 960，且長寬比至少 1.45 | 左側修行 HUD＋縱向資源，經營以右側清單顯示建築／洞天；修行／遊歷使用中央工作區，四主入口與固定返回列保留。 |
| 緊湊橫式 | 有效寬度 640–959，或橫式但不符合寬式 | 經營保留左側修行／資源與右側清單；其他群組暫收左側 HUD。分頁／返回固定，內容內部捲動，底部四入口維持單列。 |
| 窄橫式 | 橫式且有效寬度小於 640 | 經營改中央工作區，固定四主入口；分頁必要時橫向捲動，內容縱向捲動。 |
| 直式 | 寬高比小於 1.0 | 按 9/30 決策顯示旋轉提示，阻擋正式玩法輸入；轉橫後恢復原群組與分頁。 |

這些數值是版型切換的起始門檻。實作後可因字型或平台縮放微調，但調整必須同時更新本表、測試矩陣及驗收紀錄，不能只為單一截圖加入例外座標。

每個版型都必須提供：選取建築、查看與執行當前可用動作、關閉詳情、回到洞府、平移與縮放世界、降低特效，以及開啟存檔管理。直式版顯示旋轉提示；上述玩法契約在轉回橫式後恢復。

## 4. 可讀性、命中與輸入

所有正式 UI 文字維持為 Godot `Control`／`Label`／`Button` 文字，由共同 `Theme` 和 `FontVariation` 指定字型、字重與字級；不得把介面文案烘焙為背景圖或按鈕貼圖。2026-10-02 UI6-R1 採思源黑體 TW VF 400 作正文、600 作操作，粗明體 800 作章節題字，樣式入口為 `src/presentation/ui_typography.gd`。新增畫面須沿用共同字體角色，不逐頁任意退回細字重。

| 文字角色 | Godot 邏輯字級起點 | 規則 |
| --- | --- | --- |
| 說明、資源、卡片正文 | 18；密集內容最低 16 | 允許換行與捲動，不靠縮小字級塞入固定高度 |
| 按鈕、狀態與卡片標題 | 18–20 | 字重 600–700，命中區仍依觸控規格 |
| 頁面與彈窗標題 | 24 以上，依版型調整 | 優先保留辨識度，過長時換行或縮短文案 |

文字與背景必須有明確明暗對比。重要資訊放在不透明或近乎不透明的 Godot 面板上；世界背景上的狀態標籤須有實底或足夠粗的描邊。低透明度灰字不承載必要操作、成本或關閉提示。字級以 Godot 邏輯像素設定，最終仍要在實際瀏覽器 CSS viewport 和裝置縮放下檢查。

目前保留字型的動態光柵化與 hinting。Godot 的預先產生字形主要改善首次顯示新字元時的停頓；MSDF 適合大幅縮放的文字，但官方指出小字可能較不清楚，且低階手機有額外成本。只有在量測到字形首次出現卡頓時，才對常用字做有限預渲染；不能把預渲染當作字級、字重、對比或換行問題的修復。[Godot 字型與預渲染文件](https://docs.godotengine.org/en/stable/tutorials/ui/gui_using_fonts.html)

- 以 `360×640 CSS px` 作為最小支援直式視窗。畫面不得有關鍵資訊、主要按鈕或抽屜標題被裁切。
- 主要觸控目標的可點區至少約 `44×44 CSS px`；視覺圖示可較小，但命中區不可較小。
- 繁體中文正文與成本文字必須可換行或縮減資訊層級，不能以截斷資源名稱、重疊文字或縮到不可讀來塞入面板。
- 觸控在 `Control` 範圍內只操作該 UI；世界拖曳和雙指縮放只在未被 UI 或彈窗佔用的 `WorldViewport` 內處理。按鈕按下、滑出、放開與取消不應觸發世界點選。
- 每個抽屜與彈窗必須分成固定標題／關閉區和可捲動內容區；關閉控制不得放在可捲動內容末端。頁面可視高度受瀏覽器工具列、虛擬鍵盤或方向切換影響時，內容區可捲動，關閉控制始終可見並留在可視範圍內。

## 5. M2-D 驗收與證據

CLI 或直接呼叫 GDScript 的 runner 只能確認規則、場景建立與內存趨勢；它不能證明瀏覽器的 CSS 尺寸、實際命中或觸控。里程碑曾以桌面 Web 證據放行；窄版回歸問題按 M2-D-R1 重開，不把舊 DONE 當作目前全版型通過。

每次影響場景、HUD、字型、輸入、Web shell 或 export 設定的修改，至少重新驗證受影響版型，並將實際結果寫入 `docs/verification/m2-d.md`。記錄應包含匯出版本、裝置或瀏覽器、CSS viewport、方向、輸入方式、畫面紀錄、通過與未通過項。

| 最低案例 | 輸入與畫面檢查 |
| --- | --- |
| 桌面 `1280×720` | 新檔確認 HUD 目標指向聚氣／茅屋及後續 DAO2 順序；開管理欄確認資源固定、建築獨立捲動、詳情取代列表且可返回原位置；三入口可點，拖曳、滾輪縮放、歸家正常。 |
| 窄橫式 `844×390` | 空島世界仍有連續操作區；管理欄、詳情、返回與底部三入口均不越界，短詳情可收起資源；再驗單指拖曳與雙指縮放。 |
| 小直式 `360×640`、`360×480` | 確認旋轉提示可讀且阻擋玩法；轉橫後四主入口／群組分頁、選取與返回恢復。觸控命中需在實體橫式裝置另驗。 |
| 一台指定實體手機 | 直式與橫式各測一次；確認單指平移、雙指縮放、按鈕點擊、方向切換和低特效。 |

驗收時另外量測 Roadmap 已定義的冷啟動、幀時間與 50 次視圖切換記憶體趨勢。任何未持有的實體裝置或未能執行的瀏覽器案例都要標示為待驗證，不能由桌面截圖推論通過。

## 6. 實作限制

2026-10-03 UI8：核心資訊以「道印＋22 境界題字＋16 層級／正文」分層；修煉、壽元、天時正文使用同一墨色，進度條青玉、通知圖字古金只作角色裝飾。桌面三項資訊各自成行；短橫向以進度條 tooltip 承載秒數，壽元與天時併排，保留資源及導航空間。BUFF 區共用宗門完成、靈獸可餵養、機緣待決通知；固定 44 圖字控制／有限高度，依寬度僅顯示完整圖示，超出以＋N 分頁；hover 顯示名稱／效果／時間，BUFF 點開原生詳情、外側點擊關閉；通知點擊前往 canonical route，不領獎、不餵養。長壽盡段落改為層級狀態與輪迴捷徑。直向旋轉遮罩維持；遮罩下的高密度管理欄可保留資源顯示模式而暫收列表。

2026-10-03 NAV1/UI5 使用者回饋：四個主入口統一 18 邏輯字級；輪迴資格顯示「修行・輪迴」、機緣待決顯示「遊歷・機緣」，附具體 tooltip，低於 640 邏輯寬度縮為入口名加圓點。洞府系統訊息以全 viewport 水平置中，短橫向碰到左 HUD 時保留間距並讓位；經營仍沿用單頁互斥而暫收訊息。導覽 Control 在 HUD 子節點順序高於資源面板，旋轉提示仍在其後建立，避免短橫向可見按鈕被底下資源區攔截輸入。
