# 修仙人生的餘韻：文字、輪迴小傳與人際敘事研究

日期：2026-10-21。任務：`ATM-LIFE-RESEARCH`。狀態：研究與討論文件 DONE；所有設計、文案數量與實作順序均為提案，未開工。

使用者指定研究《江湖千萬人》，借鑑其文字人生、隨機事件、人際關係、結局與字體，提升 DAO2 修仙氣氛。本次要求優先於 Roadmap 既定下一內容批次；本輪不修改正式遊戲、不替使用者核定新 UI 通則。

2026-10-21 **跨研究整合規劃已交付**：與[1in8b研究（以第15節更正為準）](research/2026-10-21-1in8b-life-report-ux.md)合併取用方向，見[一世卷末整合規劃](27-life-report-and-decision-ux-integration-plan.md)。以同一當世事實層支持小傳、留痕、抉擇簿與後續帳目；分段任務與原A/B/C對照以整合規劃為準。本文件保留研究及候選原文；敘事視角已選，字體／版面與實作仍未核定。

## 已核定的討論方向（2026-10-21）

使用者選擇「有人為你寫下一篇傳記」；不採角色在生命最後自述回望的視角。小傳由旁觀的記述者敘寫，以第三人稱／省略主詞為主要候選，不直接假設記述者是遊戲內真實存在的史官、弟子或故人。

文字以本世可證實的行跡為骨架，語氣平實、克制，最後留一句餘韻；不替角色斷言未被選擇或記錄的心願、感情與臨終念頭。尚無姓名系統時以「此世修士」或省略主詞敘寫，不為此先新增人物身分功能。

語氣示例（原創候選，需有本世建屋與兩島開拓紀錄）：

> 初居山中，築屋修行。其後開拓青木、玄礦兩島，往來漸遠，行跡也漸入雲海。
>
> 一世行止，於此收卷。

本次只核定敘事視角；「一世卷末」頁內版面、F-B／F-C字體比較、題名與篇幅、保存世數及實作範圍仍待討論，不能視為全部接受或已開工。下方第二人稱研究樣稿保留為早期候選，正式文案需依本項視角另行改寫。

## 1. 核心建議

先做「這一世如何被記住」，再考慮擴充「這一世能遇見誰」。最值得先討論的是：在壽盡與既有輪迴演出之間，增加一張依真實經歷寫成的**當世小傳**。先讀定調與一件往事，再看道心、道證與轉世操作。

目前 DAO2 並非沒有氣氛資產：熄滅命燈、拆層輪迴盤、蓮花、雲霧與六道文字均已有交付。缺的是敘事上的個人差異：玩家記得自己蓋過什麼、修到哪裡，系統卻尚未替這段經歷留下一句話。建議補上此層，不推翻已接受的演出。

文字的角色是將事實轉為記憶。不可用不存在的弟子、故人、死亡原因或成就讓小傳看似豐富，也不將較低境界的一世一律寫作失敗。

### 文字蒐集是否可行？

可行，建議分兩路：

1. **靜態結構研究**：從公開頁面辨識事件 ID、條件、冷卻／去重、結局優先序、文字槽位與關係欄位，盡量記結構、分類與摘要。動態模板含函式，不能把全部原碼當 JSON，也不要用 eval 執行第三方程式來取資料。
2. **有界遊玩樣本**：記錄少量完整人生中的選擇、實際事件、結局與人物回收；選不同出身／重心作比較。每筆標註來源、年齡、上下文與是否玩家選擇；不要只摘最漂亮的結尾而失去成立條件。

本輪已確認出生、生活日誌與結局資料結構，未完成完整人生樣本矩陣；使用者截圖仍是主要結局視覺證據。後續若加做語料分析，以摘要／標籤為主，DAO2 成品文案另行原創，不搬用原作人物、專有門派、判詞或整庫事件。

有界遊玩抽樣：角色柳若兮，塞北出身；使用4倍速與遊戲自帶的命運代選，觀察至34歲，稱號槍俠、羈絆2人。日誌可見同一人物多次相遇、關係變動、人生重心變更與世界風聲；31歲的一次報恩明確回指22歲的救助。這是實際出現的因果回收樣本，不表示每條隨機事件都有後續，也不把命運代選記為代理人工策略選擇。

## 4. 前端方法帶來的額外靈感

### 4.1 結局要有條件、優先序與穩定變體

公開片段可見 `ENDINGS.find(...)`，表示依陣列順序選首個成立條目；`pickStable` 則以姓名與終年導出變體索引。啟發是：同一段人生不應因為重開結算就換一句判詞。

DAO2 可採「成立條件 → 明確 priority → 固定 ID 排序 → 穩定變體」；每個題名附來源事實與 why_selected。重要專屬事件優先於一般成長描述，再以通用題名兜底。需做候選覆蓋盤點，避免一個寬鬆高優先條件遮住大半內容。不要照搬以姓名選文，DAO2 尚未建立這種人物身分契約。

### 4.2 關係不是一個總好感

公開生命資料分開保存遇見順序、人物關係、伴侶、結義、失去的人、救命者與仇怨；結尾渲染有依關係類別呈現送別者的路徑。這使人際互動能回到結尾，而非只加某個總數值。

DAO2 可先借用「某個人記得某件事」：例如一位宗門執事的委託後續，或靈獸在世末的小動作。完整師徒、道侶、仇敵、家族屬後期新系統；不可由宗門貢獻直接推論已收弟子或有人送終。

### 4.3 日常小事讓大事有份量

出生與幼年樣本同時放入環境、家境、一次日常與數值變化。不是每句都宣告命運。DAO2 也需要採藥沾露、丹爐熄火後的餘溫、屋簷風聲等小事，讓突破與壽盡有可以回望的生活。

日常氛圍句不一定給獎，不強制彈窗，不每秒刷新，不消耗玩法 RNG；可以隨已發生事件更新訊息區的一句文字。

### 4.4 少量策略可以塑造一生

網站將人生重心及重心歷史獨立記錄，結尾可回顧階段。DAO2 可先依真實行為記錄偏向，讓反覆煉丹、開島或宗門服務有所回聲。等內容充分後，再討論玩家主動選擇「此世所求」；若只是敘事偏好就不能暗示未存在的數值加成。

### 4.5 生死之外，世界仍在繼續

首頁與出生頁用其他人的存在提供世界感；結尾把一生放回地方和人際網絡。DAO2 可在小傳末尾保留一筆物象：居所、燈、丹爐、靈獸。不可在規則會清除人界建築的情況下寫成它們真的跨世保留。遺物畫面可以是回憶，不等於可領回的實體道具。

## 7. 當世小傳的呈現提案

建議先討論「卷末小傳」：壽盡沿既有路由開輪迴頁，頁內首段為題名、判詞、短段與一至三項真實事實；完整回顧展開閱讀。原命燈與輪迴盤保留，調整比例須另做樣張，不先指定新尺寸。

閱讀順序：**舊世定調 → 此世事實 → 轉世所得／保留重置 → 確認轉世 → 既有輪迴演出 → 新世開始**。成功轉世後可重讀已封存的舊世，不能再用新世資料重算。主動提前轉世應寫作散去此身、主動重修等告別語意，不呈現命燈因壽盡熄滅。

寬式可以題簽與正文並置；844×390／800×360改橫向短題簽、一句判詞與「展開小傳」，其餘內容內捲。固定返回、收益與確認操作，正文18／密集最低16與44px命中維持。以容器與可換行文字實作，不在世界島上增設碑牌。低特效完整保留文字；禁止強制逐字播完才能轉世。

不建議直接複製參考圖所有天賦、歷程、數值卡到 DAO2：原圖為直向閱讀感的長頁，DAO2 有短橫式與世界畫面。氣氛可用少量有份量的文字建立。

## 8. 字體搭配研究與候選

網站 CSS 連結明確宣告 `LXGW WenKai TC` 400／700 與 `Noto Serif TC` 600／900；首頁 computed style 中，敘事段落的首選為文楷，主投胎按鈕首選為 Noto Serif TC 900。**這是 CSS 字族與字重宣告證據，沒有逐字形證明實際字檔皆載入，也沒有本輪實測結局畫面的全部字型。** 截圖大字有鮮明的明體／宋體筆畫觀感；精確結局字重仍待樣張核對。

| 候選 | 適用範圍 | 取捨 |
| --- | --- | --- |
| F-A：現有黑體＋字重／留白 | 所有小傳文字 | 最小變動，先確認文案本身能成立 |
| F-B：黑體操作＋文楷短判詞 | 只有短判詞／卷末引句 | 與現有輪迴文楷呼應；長段仍保持黑體可讀 |
| F-C：黑體操作＋明體題名＋文楷短段 | 完整卷末小傳 | 層次最強，也最容易變成第三套UI；須集中定義角色與比較短式 |

推薦先比較 F-A／F-B。網站字體用法是靈感，不是本次核定 DAO2 全站換字體。若後續採用新增敘事角色，必須同步 [19共用規範](19-ui-ux-guidelines.md) 與 UiTypography；不在單頁 preload 新字檔。現有輪迴字檔與 OFL 資料需按既有 manifest 核對，新增字檔另保存來源／版本／授權，並跑 runtime corpus 缺字檢查。正式 Web 不必依賴 Google Fonts 線上載入。

## 10. 內容生產規格

判詞每句約20–45字，小傳約80–160字作起始比較；不是硬性排版限制。首批提案8–12種題名，每種2–3個變體；先確保每個都能被可信條件觸發，不以數量代替品質。

每條內容至少記：`id`、`content_version`、`priority`、`required_facts`、`excluded_facts`、`title`、`verdict_variants`、`paragraph_variants`、`fallback_id`、作者／來源、使用條件與測試 fixture。候選敘事標籤可以是丹道、營造、遠行、守拙、重修；都不自動變成新的數值系統。

寫作檢查：有一個具體物象；形容詞少於動作；不替玩家宣告未選擇的愛恨；不嘲諷低境界；不每件事都寫天道震動；不要偽造對話、死人或送葬者；順境與挫折皆保留餘韻。同一事實可有不同語氣，但不能改變事實結果。

事件鏈可用「初見 → 選擇／後果 → 回聲」三節，先做少量完整鏈。避免只把隨機事件數翻倍。日常、進展、波折、抉擇與回顧是內容分類，不先承諾抽選機率；各自節奏需與既有天時／機緣推進相容。

## 11. 實作與保存邊界（候選，尚未新增欄位）

第一階段可只從當世狀態產生唯讀預覽：世次、終點境界／層級、已用壽元、轉世理由、建築狀態與正式收益。只能說當下確定的事；不提供不存在的逐年履歷。

若要求轉世後／重載仍可重讀，就不再是純UI修改。建議在轉世原子操作清除當世前生成有限 `life_record`：

```text
record_version, life_id, ended_reason, elapsed_time,
end_era_id, end_level, facts[], milestones[],
narrative_version, title_id, variant_id, frozen_text,
reward_receipt_reference
```

此為概念資料，不是 schema 承諾。保留 frozen_text 可避免內容更新後舊世換說法；ID保留供分析。具體容量先討論最近10世等有界方案，不存每秒資源流水。只記已發生的命令結果與必要里程碑；本世峰值、採集次數、關係鏈按需要加入，不能只在結算時猜測。

保存設計必須一併處理版本遷移、缺欄位 fallback、大小上限、非法文字資料、兩代復原、拒寫與重試。命令已結算但保存失敗時仍可讀同一份小傳；重試不得重抽判詞、重複輪迴或再領收益。舊檔無歷史就明示未留記錄，不能倒造完整人生。

選文使用固定事實／life ID／內容版本導出穩定變體，不消耗 gameplay 或 worldgen RNG。UI讀View；動畫、逐字效果與BGM結束均不決定收益。暫不引入 runtime LLM、通用事件腳本引擎、社交後端或新的道德數值。
