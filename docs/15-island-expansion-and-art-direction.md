## 三島是首段切片，不是世界上限

「三島」精確指祖島＋青木島＋玄礦島的築基產業驗收組合。產品名稱改為「空島」。本輪實際可玩仍為這三座，第四島及三十座以上內容尚未實作。

長期規劃以 **30 座以上具名可經營島嶼** 為容量方向，先用 36 座（含祖島）作設計盤點目標，按境界逐批驗證，數量不構成已完成內容或固定發售承諾：

| 境界段 | 盤點目標累計 | 主要增加的選擇 |
| --- | ---: | --- |
| 練氣～築基 | 3 | 祖業、林業與礦業互供；本輪已接正常版 |
| 金丹 | 6 | 丹霞首島，後續複合產地／中轉據點；先完成 RES1-D 單島閉環 |
| 元嬰～煉虛 | 18 | 同材料多產地、產量配比、加工專業化與航程 |
| 合體～渡劫 | 27 | 高階加工節點、區域物流與舊島再投資 |
| 後三境 | 36 | 成熟島群的組合與終局材料消耗 |

以上分配是 v2 設計草案，境界實際顯示名與門檻以十二境界內容契約為準，並非每境固定新增同樣數量。不能以增加空殼島取代可玩的供給／加工／消耗链。

## 島數與材料種類解耦

島嶼是一個產業節點，不是一個唯一資源 ID。多座青木型島可以都產靈木；多座礦業島可以共產下品靈石與玄銅。差異來自产量配比、開拓成本、容量、加工職能及固定航程。每島至少有一個可解釋的投資理由，不能只把倍率放大再改名字。

- 林業、礦冶、靈植、靈泉、晶脈等少數產地家族，配合有限的加工／融合材料，支撐多座島。先沿用現有材料鏈，確有新增消耗才加材料。
- 第一輪不因「36 島」新增 36 種進階物資；靈材、銅精等持續投入倉儲、運力、工坊，後續供應陣芯／修行。DAO1 既有資源逐項核對，不因此設計草案一律刪除。
- 例：近祖島的林場適合穩定回運；偏遠富木島產量較高但需要擴運力；木石混產島減少跨島供料；靈材坊專業島消耗同樣原料、提供加工優勢。這些是後續選擇示例，當前公式仍依 C1。

## 擴充前的技術門檻

目前 `IslandEconomy.ISLANDS`、固定航線與世界位置仍包含首批專用定義，不能聲稱引擎已驗證 36 島。下一批擴充先把 island_id、產地家族、era_id、產量、容量、配方許可、航線端點／週期與 art_profile 整理成可驗證的內容契約。

材料用 resource_id 引用，不由 island_id 推導。存檔保持穩定 island_id 與規則版本；新增／移除定義有遷移、拒絕及復原測試，未知島或在途貨物不得靜默丟棄。首批既有 home／wood／ore ID 不改名。

島群總覽需要分區／篩選或虛擬清單，不能把 36 個按鈕塞在目前底部橫列。場景只載入當前島及必要鄰接視覺，未顯示的經濟仍由純規則結算；必須先通過離線、切島記憶體與 Web 包體預算，才逐批放量。本輪不建立 36 個空場景或通用伺服器。

## 首批圖層與操作契約

`assets/abode/res1c3/` 保存四張 runtime PNG、兩張規劃參考及六份手寫提示詞、manifest。內建 image_gen 生成；沒有使用外部 API 金鑰。島體不含可開拓建築；地標為獨立複合建築 Sprite2D，只有開拓後顯示。參考合成圖不作 runtime 世界；不複製其他遊戲美術或宣稱其商用授權。

Pipeline：scene_mode / layered_raster / separate_props + interactive_scene_objects / trigger_zones / Godot project-native。每座新島地形畫布 1536×1024，runtime 等比例寬 780；地標寬 440、中心位於島座標 (0,-170)。點擊區與相機由 `island_world.gd` 明確定義，不由圖片像素決定收益；本遊戲無島上行走角色，因此本輪無角色碰撞／遮擋需求。

正常遊戲：經營 → 空島 → 築基後「保留原檔並啟用空島」→ 分別開拓青木／玄礦（每島由祖島支付靈木20＋下品靈石10）→ 原料互供、持續加工、成品運回祖島 → 消耗 T2 升級。源檔先保存、歸檔核驗後才提交新經濟，失敗可重試。仍保留獨立 preview namespace 供驗收，不用測試檔覆寫玩家正常進度。
