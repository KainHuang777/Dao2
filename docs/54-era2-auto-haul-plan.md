# 築基自動航運與祖島製造

**任務 `ERA2-AUTO-HAUL`，2026-11-08。** 先做築基一層的供給循環，讓玩家開拓產地、在祖島下單、回到晉階。取自動運輸和玩家主動製造的分工，驗證它能否減少找路和重複啟航。調整依 [R1 玩家回饋與重現](development-status.md#era2-playtest-r1) 排序。

R1 從外島加工檔重現「玄礦銅精 0、祖島 1」，接好兩條線後第 221 模擬秒才湊齊升階材料。這筆紀錄用來定位卡點。正式 A/B 對照用同版集中製造檢查點，才能分辨自動啟航省下多少操作。[試玩方法](53-era2-playtest-plan.md)

## 第一階段的玩家流程

1. **開拓即開通原料回運。** 玄礦島開通玄銅與下品靈石，青木島開通靈木。三條既有原料航線依庫存、運量、在途貨物及祖島容量自動出航。保留現行基礎每趟上限 10、航程 10 秒及各自的預設庫存政策。
2. **製造由玩家下單。** 祖島選銅精或靈材，選單批或持續；產物完成後入祖島。玩家先前下單的持續製造缺料時等待補給，材料足夠後沿既有批次規則續作。待運、在途和祖島可用庫存分開計算，只有可用量能扣料。
3. **缺料留在原配方處理。** 顯示祖島可用／每批需求、來源和下一步。未開島引導開拓並回原配方；有實際貨物才顯示到貨倒數；若受祖島容量、手動停航或保留量限制，才提供對應入口。晉階缺料同時呈現靈材與銅精缺額，能進配方也能回原晉階目標。沿用共用分頁、成本格和關閉操作。[介面規範](19-ui-ux-guidelines.md)
4. **運輸頁負責看瓶頸與升級。** 來源累積且船已滿載時，載量升級有用；貨裝得下但等船時間長時，航速才有用。首輪沿用既有運力升階，待試玩顯示有獨立的航程問題再設計航速。停航、保留量與目標庫存放在完整管理。

### CORE 優先檢查

- 從 [IslandEconomy](../src/simulation/island_economy.gd) 的 `HUB_ROUTES`、`open_island` 與 `_seed_supply_routes` 入手。現有播種只涵蓋已符合條件的 SUPPLY 航線集合。新增行為限上述三條 hub 原料航線，採現有設定與 tick，並讓首次成功開拓後的 View 立即讀到航線狀態。
- 核對 [SaveManager](../src/persistence/save_manager.gd) 的首島候選交易與 [EconomyProfile](../src/economy/economy_profile.gd) 的獨立存檔流程。首輪優先驗新檔。既有航線的停航、目標、保留量及等級優先於自動預設。既有檔若之後採用此政策，透過明確的版本化啟用路徑處理。舊外島檔沿用原有集中製造遷移與原檔歸檔。已扣料工作及在途貨物按原狀完成。
- 驗收首島付款和新航線同一候選交易，開拓拒絕、拒寫、重送與重載皆不重扣或重建航線。涵蓋滿倉停運、出庫後續運、在途存讀、在線／離線等價、輪迴後清除本世物流。優先復用 `hub_economy_runner.gd`、`hub_onboarding_runner.gd`、`econ_r1_play_runner.gd` 的隔離資料與案例，先 `-Only ... -List` 核對選取，再跑受影響的 L1。
- CORE 交給 AGY 時先給一條航線及可驗收案例，允許範圍為相關核心、保存／應用接線與指定 runner。UI 由 Codex 單獨接手。Codex 審查 diff、核對工具日誌並獨立跑驗收。已確認本機 AGY CLI 1.1.13，先前無互動權限檢查曾拒絕啟動終端。若工具仍拒絕，Codex 接回該段；以實際檔案和 runner 結果驗收。[先前 AGY 探針](development-status.md#econ-r1-f-l3-batches)
