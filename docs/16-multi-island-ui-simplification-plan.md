## 1. 方向與參考依據

採用「島上看產出、集中選配方、集中管運輸」的日常流程。各島保留地方庫存、專用配方與實際運輸；集中的是操作入口。維持仙俠紙底、青玉按鈕與既有 Godot 世界。

使用者第二張圖可直接確認 Smelt Recipes 使用相同大小的配方卡，常態呈現名稱、耗時及原料→產物關係。第一張圖則顯示目前祖島常態鋪滿庫存文字，基本操作被推到捲動區後段。[Idle Planet Miner 開發者商店介紹](https://play.google.com/store/apps/details?id=com.TironiumTech.IdlePlanetMiner)確認採礦行星升級、smelting／crafting 的玩法分工。製造與運輸的集中入口是本作設計建議；本輪未操作該遊戲，不將其精確航運介面、公式或槽位規則當成已驗證事實。開發者網站子頁讀取失敗，未作證據；附圖僅供結構參考，不複製圖示或皮膚。

## 3. 入口與返回

底部維持洞府／經營／修行／遊歷。經營頂部變成 **洞府建築／空島／製造／運輸**，固定返回洞府。不再新增底部主按鈕或 More。

Canonical route 工作方案：保留 `buildings`、`outposts`（顯示空島），新增 `manufacturing`、`transport`。在 `feature_navigation.gd` 統一註冊；選中島／配方／航線、篩選及捲動位置是呈現狀態，不加進玩家經濟快照。群組記憶延續既有行為。

- 點世界島體／島名：同一空島基本詳情。點已建工坊：製造並定位本島產線。點真實在途提示：運輸並定位該航線。
- 空島詳情的「製造」「運輸」是情境捷徑，帶 island_id 篩選；全島清單入口可清除篩選。製造→缺料→運輸帶相關 resource_id，不自動改設定。
- 點配方列主體只展開詳情，啟動／停工是獨立動作。返回詳情前的清單位置；Escape 先回清單，再返回洞府。切主分頁關闭舊詳情。
- 未開拓島仍可查條件，開拓費只從祖島支付。保留「保留原檔並啟用空島」與三島檔延伸丹霞的既有遷移入口，不自動替玩家啟用。

## 4. 資源島基本詳情

常態只保留：島名與職能、主產物當地可用／容量、有效採集率、採集／倉儲兩個升級項，以及製造／運輸捷徑。只列本島生產的原料，青木1項、玄礦2項、丹霞2項；加工物與輸入庫存移至製造詳情。

示例（示意庫存，非玩家存檔）：青木島｜靈木 80/100｜採集 2/秒；採集一階→二階 4/秒，倉儲一階→二階 200；費用由現有核心／View 提供並明示祖島支付。只展示一項最高優先狀態，如「靈材缺下品靈石」，可點前往處理。祖島只顯示身份／產線摘要及洞府建築捷徑，不重建全部資源面板。

不新增採集暫停：目前專業島没有該命令。加工停止放在製造，運輸停止放在運輸；若後續需要全島停產，另列規則契約。

## 5. 製造：集中配方、保留加工地

採 Idle Planet Miner 附圖的配方閱讀順序，緊湊卡片不保留大面積空白。寬工作區兩欄、狹窄或高度受限一欄。常態最多四組資訊：**產物／加工地、原料→產物、有效耗時、狀態及一個主動作**。完成進度只出現在正在工作的產線，不讓全部卡片都畫進度條。

提供「精煉／合成」兩個配方分類（呈現分類，不改 recipes）：精煉包含靈材、銅精、丹液、中品靈石；合成包含陣芯、築基丹、金丹丹藥、符咒。各卡標加工地；工坊不增加新槽位。起手以卡片為主，已運轉島的產線摘要置頂，可直接進詳情或「本批後停止」。

詳情取代清單同一工作區，呈現各原料「此地可用／需求」、到貨量／倒數、輸出可用／容量，並提供單批、指定批數、持續的模式選擇，預設單批以延續現有最小動作。原料保留量放「進階設定」。缺料時主動作顯示缺項：本島採集原料導向本島採集升級；外島供應導向實際可補貨航線；共用靈力導向祖島設施。不能將丹霞缺當地靈草錯導到丹霞向外送草航線。無工作時不能假裝已有持續等待工作（craft 首次缺料會拒絕）。

每島一條產線，祖島五配方互斥。已有工作選另一配方顯示「本批後切換」，送既有 switch_processing；等待狀態 remaining=0 可立即換配方／停止，進行中按本批結束處理。卡片不可讓多配方同時看似運轉。缺料等待／產物滿倉是已存在工作狀態，與尚未開始區分。

## 6. 運輸：路線列＋按需設定

常態每條一列：**貨種、來源→目的、狀態、啟停**；運力效果（現有10或20／10秒）及正在到貨倒數可占第二行。多資源同方向可視覺分組，但每條 route_id 仍各自啟停，不把不同保留量改成同一政策。原七條航線全部保留：wood_ore、ore_wood、timber_home、bronze_home、grass_home、herb_home、liquid_home。

點「設定」取代清單，保留來源保留量、目標庫存與保存按鈕；運力升階是獨立付費按鈕，顯示升前／升後吞吐與祖島材料費。配置草稿不被每秒 refresh 覆寫；返回未保存設定以明確提示處理，不靠自動寫入。

- 啟用第一條未配置航線使用**既有**預設 reserve=0、target=100、level=1；有設定的航線沿用原值。未開拓端點時禁用並顯示開拓捷徑。
- 停航文案「停止新出航；當趟仍會到貨」。重新啟動不重送既有 cargo。付費升階沿用 enabled 原值，不能偷把停航航線改成啟用（現有舊按鈕傳 true，重構時須修正）。
- 正常無貨不標錯誤。按條件讀成「來源無餘貨」「已達目標庫存」「目的倉滿」；運力不足必須有來源堆積／有效吞吐證據，不能只看 trip 空就猜測。
- 不要求逐趟派遣、不新增畫線、不加自動配置全網。整體「一鍵啟用全部」涉及多命令與部分失敗，首輪不納入。

## 7. 數值語意與提示

現有 inventory.reserved 是**目的倉空間預留**：在途貨物即將入庫＋加工產物即將入庫；並非兩種可花庫存，也不是尚未扣除的加工原料。加工啟動已扣原料。重構詳情分開顯示：當地可用、在途到貨、加工待完成、容量預留。以 jobs／trips 對照 View，不能將 reserved 再加到在途總量。

左側既有庫存表示维持一致，不偷偷換成各島總和。具體製造可否啟動必須用加工地可用及既有 GLOBAL 資源規則；祖島金錢／靈力不搭航船。缺料後仍能理解「全世界有，但本地未到」。

訊息優先序：保存失敗／操作拒絕 > 未解鎖／未開拓 > 缺料／滿倉 > 運轉。成功不常駐佔一整行；保存失敗持續顯示重試入口，重試只保存、不再送 craft／configure_route。pending 切方及停止安排是工作狀態，不能短暫消失後無從查詢。

## 8. 版型

沿用 docs/07 的横式策略與既有字體／44 CSS px 命中。空島基本詳情維持不超400邏輯像素右欄，保留世界安全區及左HUD。製造／運輸改中央工作區並暫收左側修行／資源，所需本地材料放在配方詳情；離開後恢復原資源三態。這是本次經營集中頁對 docs/12 原「經營一律右欄」的有界修訂。

1280×720：製造兩欄卡片、運輸一列一航線。844×390／800×360：單欄短列，固定頁籤／返回／底部導覽，內容 Godot 內部捲動。小於640的橫式中央工作區；直式360×640／360×480維持旋轉遮罩，轉橫保留選擇。不得把參考圖直式照搬為正式直式玩法或固定畫布。

採 Container、錨點與集中 layout；可用寬度決定欄數，不縮字、不用外部瀏覽器捲軸。內容更新復用節點，只在 recipe／島／route 集合變更重建，沿用值比對保護進度尺寸避免重現 reflow 性能問題。
