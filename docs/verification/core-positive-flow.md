# 2026-09-23 核心正流程與資源可達性稽核

本紀錄保留 2026-09-23／25 的正流程證據；當時「M2-D IN_PROGRESS」是歷史狀態，2026-09-28 桌面放行及後續窄版回歸見 [目前狀態](../development-status.md) 與 [REF-A](ref-a.md)。

## 結論與問題根因

從全零新檔逐步建造時，原先只有靈氣與靈木的畫面採集入口；木屋卻先要求 `money:20`，而木屋才是 `money` 的首個自動產線，因此流程在木屋前斷開。舊版練氣期資源面板允許手動採集所有已解鎖的 basic 資源；本輪在 v2 資源總覽補齊這條命令入口。

另一個斷點是場景每幀呼叫 `GameSession.advance_time(delta)`，原函式逐次截斷不足 60 秒的間隔，正常幀率下永遠不滿一個 tick。修正後不足一分鐘的餘數跟隨 `GameState` 入存檔，線上分段與離線重開都能完成下一個 tick。產出仍依既定 60 秒／tick 結算；HUD 顯示倒數。

此外，模擬器移植來的自動晉階在首個 tick 會立即扣掉茅屋產出的靈氣，與正式畫面的手動「修為晉階」入口衝突；現在只累積修煉時間，玩家送命令時才扣料。原本的境界／道心倍率只乘資源定義的零基礎產率，沒有乘建築產率，且 `get_view()` 顯示的產率又與實際推進不一致；兩條路徑已統一。採石場的玄銅效果原本對著永遠鎖住的資源，現於採石場 1 階解鎖。建築詳情原只用庫存決定按鈕可用狀態，會對未滿前置的聚靈壇顯示可按；目前與核心 Era／前置檢查一致，並顯示缺少的建築等級。

本期十種建築（茅屋、木屋、林場、採石場、靈植場、聚靈壇、錢莊、靈石庫、木料庫、靈草庫）的首建成本與前置，已由 `tests/core_positive_flow_runner.gd` 從全零新檔逐步支付；主流程不直接增加庫存。測試接著靠實際產出與時間完成練氣 10 層、首次突破、輪迴及下一世重建茅屋。它還驗證六條已建產線在一個 tick 後實際入庫、茅屋升級提升產率、靈氣首分鐘不被自動晉階扣光、分幀／一次推進等價、餘數存檔及離線承接、先前被誤標為靈石的金錢按鈕可送採集命令、境界與道心倍率反映於畫面。

## 測試策略修正

舊 runner 多用一次 `advance_time(60)`，也會直接指定資源、建築或境界狀態，適合規則邊界測試，卻無法證明新玩家能走到該狀態。往後改動建築費用、解鎖、採集、產率、時間或存檔時，先跑不注入庫存的 `core_positive_flow_runner.gd`，再跑對應單元／邊界 runner；發佈前仍需真實 Web 操作。

## 2026-09-25 後續節奏與 HUD 修正

前文的 60 秒／tick 與倒數描述保留作 2026-09-23 的歷史證據；目前規則已改為每 1 秒結算一次，產率定義本來就是「每秒」，建築成本與產率數值均未加速。累積 60 秒仍等於 1 祀，壽元秒數與修煉需求維持原值。線上每秒入庫，未滿一秒的餘數入存檔；舊版未滿 60 秒的餘數仍可讀取，並於下一次時間推進按新步長結算。離線的 24 小時固定產率區間合併計算，避免逐秒執行 86,400 次完整資源公式。

`GameSession` 既有 `era_id`、`level`、修煉秒數與壽元資訊未移除；問題在 HUD 把境界、層數、修煉與壽元擠在同一長行。現分成醒目的境界／層數行與次級修煉／壽元行。靈氣等資源改顯示兩位小數，首秒的小額產出不再因整數截斷而看似沒有變化。`RULES_VERSION` 升為 `core-flow-3`；瀏覽器與手機版型仍待 M2-D 實測。
