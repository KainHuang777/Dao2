## 0. 先講結論

1in8b 最值得 Dao2 借鏡的不是「人生模擬」題材，而是它把**一次完整人生變成一張可閱讀的結算文件**：每個決定都有代價與事後收據，每年有取樣，死亡時把數值、事件、財務、地圖與人際關係整理成可回顧的層級。Dao2 目前輪迴面板只有「預期道心／道證／傳承」的公式預覽，缺少「這一生實際發生什麼」的紀錄。

建議 Dao2 做三件事，優先順序如下：

| 優先 | 提案 | 價值 | 風險 |
| --- | --- | --- | --- |
| P0 | **一生帳簿（Life Ledger）**：被動記錄資源產出、消耗、溢出、年度快照、里程碑、抉擇 | 讓壽盡報告有真實資料，不改玩法 | 低；只觀察不改變規則 |
| P0 | **壽盡報告（道途結算）**：生平摘要＋資源流圖＋大事記＋抉擇簿＋輪迴預覽 | 直接回應「不只道心道證」 | 中；UI 與存檔欄位 |
| P0 | **抉擇卡資訊升級**：效果副標、代價／所得事後收據、事件偏好標籤 | 提升每一次選擇的可理解性 | 低 |
| P1 | **年度時間帶＋歷世比較**：80／120 格人生縮圖、道心道證跨世曲線 | 長期留存與重玩動機 | 中；存檔容量 |
| P2 | **順勢而為（自動抉擇）與道心寄語** | 減少重複點擊、增加個人痕跡 | 中高；可能削弱抉擇感 |

**不建議照搬**：每年選「重心」的核心迴圈、172 國真實資料、1500 條流水帳、分享圖卡、16 種自動性格。Dao2 是放置型修仙，不是年度人生模擬；抄錯層級會讓玩家忙於填表而不是經營洞府。

以上所有 UI 提案都以 Godot `Control` 實作，HTML／JS 僅作 Web 容器；不引入 React／TypeScript 或把核心搬到網頁。

## 2. 1in8b 的產品定位與核心循環

### 2.1 定位

- 免費、免註冊、15+ 的人生模擬網頁遊戲。
- 隨機出生於 172 個國家之一，可選「現代／1950–2025 過去／未來／隨機」。
- 一場人生約 30／60／90 分鐘，可 1×–16× 加速、暫停、自動抉擇。
- 數值只有四項：健康、幸福、知識、人際關係（0–100）。
- 明確宣告：數值**提高機率，不保證結果**。

這個「不保證」是整個 UX 的基石：玩家做的是風險管理，不是解方程式。

### 2.2 核心循環

```text
出生（隨機國家／時代／家庭）
  → 每年選一次「重心」（6 歲起）
  → 數值與時間分配改變
  → 不定期跳出抉擇卡（求學、工作、戀愛、遷徙、治療……）
  → 抉擇改變後續機率，插入事件與事實卡
  → 5／15／30／50／70 歲暫停提問，可留一句話
  → 死亡
  → 死亡紀錄：一生資料可視化、事件回顧、分享
  → 再玩一生
```

### 2.3 節奏設計

- 年度重心是「低頻決策」；抉擇卡是「高影響決策」；隨機事件是「敘事噪音」。
- 暫停點（5／15／30／50／70）把長流程切成五幕，讓玩家有機會反思與留字。
- 加速與自動抉擇是「不想錯過後半生」的補救，不是預設玩法。
- 一場 30–90 分鐘，和 Dao2 一世 80 年×60 秒＝80 分鐘（Era 1）幾乎同量級；但 Dao2 是背景生產，1in8b 是前景選擇。

**對 Dao2 的啟示**：Dao2 已經有「低頻決策」（破境、輪迴、境界抉擇）與「背景生產」。缺的是把兩者在中途與終點**接起來的敘事層**，而不是再增加一層年度選單。

## 3. 系統拆解

### 3.1 數值與時間

- 四項數值皆 0–100，年度重心分配成長權重。
- 重心同時影響「時間投入統計」，死亡報告會顯示一生時間花在哪裡。
- 興趣有等級，會隨時間累積。
- 健康、收入、吸菸、慢性病等會進入死亡機率模型；壽命用出生國／性別生命表加權。

Dao2 對應概念不是健康／幸福，而是**壽元、境界、道心、道證、資源存量與產能**。Dao2 的「時間」已有明確單位：60 秒＝1 年，Era 1 上限 80 年、Era 2 上限 120 年（`content/eras/era1.json`、`era2.json`）。這讓「年度快照」非常便宜：一世最多 80–120 列。

### 3.2 抉擇卡（Decision Card）

1in8b 的抉擇卡資訊層級很清楚：

1. 標頭：暫停／小抉擇／家庭／重大抉擇＋年齡與年份。
2. 標題與敘事本文。
3. 選填「事實盒」：真實統計，左側色線，等寬字。
4. 選項：編號、主標、**效果副標**（例如「知識↑ 幸福↓」）。
5. 選填姓名輸入、反思 Textarea。
6. 自動抉擇倒數條、「從現在起交給自動」。
7. 選後寫入紀錄：`決定：<選項>`，結果另成一則大事件，可能附事實盒。

關鍵不是卡片長得多漂亮，而是**每個選項在按下前就知道方向，按下後知道發生了什麼**。

### 3.3 隨機事件與「事實盒」

- 事件分為一般、重大、失去、死亡、抉擇、里程碑等 kind。
- 事件可帶 `fact`：一句真實世界統計，讓虛構人生有現實重量。
- 事件有星號、行動標記、自動標記，供結算時挑選「難忘時刻」。
- 事件依年齡、國家、狀態加權；不是純均勻隨機。

**可借鏡**：Dao2 的奇遇已有境界／天候／時辰偏好（`src/simulation/fortune_system.gd`），但玩家看不到「為什麼是這個事件」。把偏好轉成**定性標籤**（「契合：金丹」「天時：子時」）即可，不必公布權重。

### 3.4 自動抉擇

- 可選四組詞對、十六種「質地」作為傾向。
- 有傾向時，自動選擇偏向該質地；沒有傾向時跟隨國家多數選擇。
- 自動模式有倒數條；點擊卡片或 Textarea 會停止。
- 可針對單一抉擇「從現在起交給自動」，也可關閉暫停提問。

**可借鏡但需縮小**：Dao2 的奇遇若加入「順勢而為」，只需一個 5–8 秒倒數與「本次／本世」兩段式開關，不需要十六種性格。且應只作用於奇遇，不作用於破境、輪迴、境界抉擇等不可逆操作。

### 3.5 死亡與結算

死亡紀錄的資訊架構（由原始碼與文案整理）：

| 區塊 | 內容 |
| --- | --- |
| 身分 | 姓名、出生／死亡年、享年、死因、出生地 |
| 生命敘事 | 一段人生摘要、教育、最後職業、伴侶、子女（含先逝） |
| 對照 | 與同世代／出生國平均壽命比較、存活曲線 |
| 快樂 | 最快樂的一年、幸福度人生地圖 |
| 關係 | 葬禮出席者、家庭成員、五位同生者 |
| 時間 | 一生時間分配（各重心累計） |
| 財務 | 收入百分位、資產曲線、年度資產增減、稅費與支出堆疊、遺產分配 |
| 事件 | 難忘時刻（加權挑選）、完整年表（可依年代篩選）、日誌 |
| 統計 | 抉擇數、自動抉擇數、最高收入、居住過的國家 |
| 延伸 | 分享卡、連結、紀念館、重播最後一刻 |

其中對 Dao2 最有用的三個結構：

1. **雙軌時間序列**：收入百分位與資產曲線共用年齡軸，下方再用窄帶標示職業與投資配置。
2. **年度格子地圖**：十欄方格，每格一年，顏色編碼幸福度，外框標平均壽命。
3. **加權難忘時刻**：不是把 1500 條日誌倒給玩家，而是先星號、再按 kind 權重、再平均取樣、同類去重。

### 3.6 財務圖表

- 兩張 SVG 折線／區間圖：收入在國內與全球的百分位、淨資產隨年齡變化。
- 圖下方有「就業／投資配置」窄帶，對齊年齡軸。
- 可折疊的五年間隔數值表。
- 支出用堆疊橫條：稅、食物、住房、交通、醫療、教育托育、其他、儲蓄。
- 年度淨資產增減逐項列出。

**這正是 Dao2 壽盡報告最該學的地方**：不是畫漂亮折線，而是讓「賺了什麼、花到哪、溢出多少、最後剩多少」在同一軸上對得起來。

## 4. 畫面與資訊設計拆解

### 4.1 視覺語言

CSS 變數（亮色）：

| 角色 | 色值 |
| --- | --- |
| 紙底 | `#EBF0ED` |
| 卡片 | `#F7FAF8` |
| 主墨 | `#13212A` |
| 次墨 | `#4A5A61` |
| 規則線 | `#C7D2CE` |
| 朱紅強調 | `#8C1D3C` |
| 青綠印章 | `#0F6E68` |
| 金 | `#9C7020` |
| 好／壞／警告 | `#2B7A4E`／`#B0362B`／`#A8730F` |
| 人生格子漸層 | `#F3E2B3` → `#7FBF86` → `#0B5C63` |

字體：標題襯線（Noto Serif TC／宋體）、正文無襯線（PingFang／Noto Sans TC）、數字等寬（IBM Plex Mono）。這個組合讓「文件感」與「資料感」並存，和 Dao2 的紙張／玉石材質方向相容。

### 4.2 元件

- `.grid10`：十欄等寬、3px 間隔、方形格；當前年外框、平均壽命內縮框、死亡格深色。
- `.lchart`：最大寬 460px、可鍵盤聚焦、`touch-action: pan-y`，避免圖表吃掉垂直滾動。
- `.flowgrid`：兩欄，窄螢幕變一欄。
- `.sbar`：8px 堆疊條。
- `.stat`：標籤／條／數值三欄，數值等寬。
- `.dec`：選項卡左側 1.6em 編號欄，主標粗體＋小字副標。
- `.dec .fact`：青綠柔底、3px 左線、12px 等寬字。
- `.dcert`：文件卡、頂部色帶、大姓名、等寬日期與享年；窄螢幕兩欄變一欄。
- `.moments`：3.2em 年齡欄＋事件文字。
- `.estate`：金額右對齊。
- 86 個 media query；長語言標籤寬度另調 6.6／7.4em。

### 4.3 響應式與可及性

- 圖表與表格在窄螢幕改成單欄；不是縮小整張圖。
- 圖表有文字表格替代，資訊不只靠顏色。
- 選項卡與輸入區在手機上保持可點；倒數條不會遮住主要按鈕。
- 文件卡在窄螢幕改單欄，避免橫向捲動。

**Dao2 必須遵守 `docs/07`**：360 CSS px 最小寬、44–48px 觸控、不可固定像素座標、不可用瀏覽器捲軸逃避版面。1in8b 的「圖表可聚焦＋數值表替代」值得直接採用。

## 5. Dao2 現況與落差

### 5.1 已有基礎

| 檔案 | 現況 |
| --- | --- |
| `src/domain/game_state.gd` | 有資源、建築、技能、丹藥、Buff、境界、宗門、奇遇、境界抉擇；**沒有一生紀錄或歷史帳簿** |
| `src/simulation/time_advancer.gd` | 每 tick 計算產率、容量、資源增量與溢出，並推進時間；是產出帳簿最自然的掛點 |
| `src/simulation/reincarnation_rules.gd` | 壽盡或建塔可輪迴；計 rewarding、重置狀態、發放起始資源；**沒有保存前世快照** |
| `src/presentation/reincarnation_panel.gd` | 只有公式預覽：B 總和、預期道心、預期道證、傳承比例 |
| `src/presentation/reincarnation_sequence.gd` | 3.4 秒動畫與結果卡；獎勵在規則層已發放 |
| `src/presentation/fortune_modal.gd` | 奇遇標題／描述／偏好標籤／選項按鈕；成本顯示原始資源 ID；無效果副標、無事後收據、無帳簿 |
| `src/presentation/abode_hud_controller.gd` | 系統訊息最多 50 條，僅記憶體，不持久化 |
| `src/simulation/offline_settlement.gd` | 離線結算報告：離線時數、有效 tick、 forfeited、年齡、停止原因；可作為「報告資料物件」範本 |
| `content/eras/era1.json`、`era2.json` | 壽命 80／120 年；60 秒＝1 年 |

### 5.2 主要落差

1. **沒有「這一生」的資料物件**：輪迴只留下總數，沒有過程。
2. **資源只知道現在有多少**：不知道產出、消耗、溢出、峰值。
3. **抉擇沒有回饋閉環**：奇遇按下後只更新一行狀態訊息，沒有「代價／所得／餘量」。
4. **沒有年度取樣**：錯過中期，就只剩開頭與結尾。
5. **沒有跨世比較**：輪迴次數增加，但玩家看不到自己每一世怎麼變。
6. **訊息不持久**：HUD 50 條訊息重開即失，無法成為回憶。

## 7. 設計提案：一生帳簿（Life Ledger）

### 7.1 原則

- **只觀察，不裁決**：帳簿不改變產率、不掉落、不消耗 RNG、不發獎勵。
- **由狀態差異得出事實**：不重算公式，避免與規則層分叉。
- **可捨棄**：帳簿遺失或格式錯誤時，遊戲可繼續，報告顯示「此世紀錄不完整」。
- **版本化**：`schema_version` 與存檔版本一起演進；舊存檔 zero-fill 為空帳簿。
- **有上限**：年度快照與事件數有上限，避免無限成長。

### 7.2 資料模型（草案）

```gdscript
# GameState 新增（預設空字典，舊存檔相容）
var life_ledger: Dictionary = {}
var past_lives: Array = []          # 每世一份摘要；上限 5–8
```

單世帳簿：

```gdscript
{
  "schema": 1,
  "life_index": 3,
  "era_start": 1,
  "era_end": 2,
  "age_start_seconds": 0.0,
  "age_end_seconds": 4740.0,
  "lifespan_max_seconds": 4800.0,
  "started_at_unix": 0,             # 可選；離線不依賴
  "totals": {
    "dao_heart_start": "0",
    "dao_heart_end": "132",
    "dao_proof_start": 0,
    "dao_proof_end": 11,
    "decisions": 14,
    "fortune_encounters": 9
  },
  "resources": {
    "lingli": {
      "start": "0", "end": "2550", "peak": "3120",
      "produced": "12430", "gained": "310",
      "spent": "9880", "overflow": "210"
    }
  },
  "yearly": [
    {"y": 1, "era": 1, "realm": "realm_human", "net": "120",
     "lingli": "120", "money": "30", "flag": ""}
  ],
  "milestones": [
    {"age_year": 12, "kind": "breakthrough", "id": "era_2",
     "text": "築基破境，入 Era 2"}
  ],
  "decisions": [
    {"age_year": 31, "kind": "fortune", "id": "enc_ancient_cave",
     "option": 1, "label": "探入洞窟", "costs": {}, "rewards": {"money": 30}}
  ],
  "buildings": {"start": {"hut": 1}, "end": {"hut": 5, "farm": 3}},
  "journal": [{"age_year": 80, "text": "此生無悔"}]
}
```

`past_lives` 只存摘要與可選的年度序列；建議：

- 最近 1 世保留完整 `yearly`。
- 其餘保留 `totals`、`resources` 總計、`milestones`（最多 20 則）、`decisions`（最多 20 則）。
- 超過上限時丟棄最舊的完整序列，但保留一行摘要。

### 7.3 掛點

| 事件 | 位置 | 記錄 |
| --- | --- | --- |
| 生產 tick | `time_advancer.gd` 的 `advance` | `produced`、`overflow`、資源峰值；跨過整年時寫 `yearly` |
| 指令消耗／獲得 | `GameSession` 執行指令前後比對資源 | `spent`／`gained`；不逐個改 `command_processor` |
| 建築升級 | 指令成功後讀 `buildings` 差異 | `buildings`、里程碑 |
| 破境／換 Era | 指令結果的 `era_advanced` 事件 | 里程碑、`era_end` |
| 奇遇 | `fortune_system.resolve` 或 `GameSession` 包裝 | 抉擇、成本、獎勵、事後收據 |
| 輪迴 | `reincarnation_rules.apply_reincarnation` | 先封存舊世，再重置；避免重複封存 |
| 離線 | `offline_settlement` 內呼叫的 `TimeAdvancer` | 自動繼承生產帳；另記 `offline` 標記 |

**重要順序**：封存必須發生在「獎勵發放與狀態重置」之前。否則前世 `dao_heart_end` 會混入下一世的傳承獎勵。

### 7.4 年度快照

- `60 秒＝1 年`，以 `total_elapsed_seconds` 為準，不依幀率。
- 每次 `advance` 後計算 `floor(age/60)`；若跨年，補寫跨過的年份。
- 一世最多 80／120 列；每列只存 3–7 個關鍵資源與淨值，其餘由 totals 補。
- 大數用現有 `AmountCompat` 序列化；圖表用比例正規化，不直接轉 float 相加。

### 7.5 與存檔／版本

- `duplicate_state`、`to_snapshot_dict`、`from_snapshot_dict` 補 `life_ledger` 與 `past_lives`。
- 舊存檔沒有欄位時預設 `{}`／`[]`；不推導、不重發。
- 帳簿 schema 不認識時保留原字典但不渲染，避免整份存檔失敗。
- 存檔大小：以一世 80 年、7 資源、每年 4 個數字估算，約 2–4 KB JSON；完整 5 世仍在數十 KB 內。若超過上限，優先裁 `yearly`，不裁 `totals`。

### 8.3 區塊細節

#### A. 生平摘要（不給評分）

- 享年、最高境界、道心、道證、傳承、抉擇數、奇遇數。
- 一句 deterministic 的「生平評語」，由三個片段組成：
  - 最高產資源（例：「以靈力起家」）
  - 最高建築或境界（例：「以丹火收束」）
  - 抉擇傾向（例：「九次奇遇，三次破境」）
- 不做 S／A／B 評級，不比較玩家排名；避免把一生變成考試。

#### B. 資源流圖（核心）

每個資源一列，左右分歧：

- 左：消耗（朱紅）
- 右：生產＋事件獲得（青綠／金）
- 疊影：溢出（斜線或較淡色）
- 末端：淨值（正負號＋顏色＋文字）
- 右側：峰值與期末存量

窄螢幕改成「一資源一張小卡」，卡內上下堆疊，不壓縮成 2px 線。

資料表替代：

| 資源 | 期初 | 生產 | 事件 | 消耗 | 溢出 | 期末 | 峰值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 靈力 | 0 | 12,430 | 310 | 9,880 | 210 | 2,650 | 3,120 |

**圖表必須回答三個問題**：

1. 哪個資源是瓶頸（產出高但溢出高）？
2. 哪個資源被大量消耗（ upgrades／丹藥／宗門）？
3. 這一世的淨成長是否真的來自生產，而不是事件一次性給付？

#### C. 壽元圖

- 橫條顯示：基準壽命、丹藥加成、天賦加成、境界法則（`lifespan_flow_ratio`）。
- 顯示「已用／上限」與「剩餘」。
- 不畫 1in8b 的存活曲線，因為 Dao2 沒有死亡機率模型；畫了會是假資料。
- 若曾服用壽元丹或轉換境界，標記時間點。

#### D. 人生帶

- 10 欄方格，每格一年，依 `yearly` 淨值或境界著色。
- 死亡／提前結算格加深；當前選取格加外框。
- 顏色不足以表達時，加小符號或文字（例如 `+`／`-`），並提供「列表」切換。
- 點擊／鍵盤左右鍵選年，顯示該年：境界、三項主要資源、當年事件。
- 若某年沒有快照，顯示「無紀錄」而不是偽造 0。

#### E. 大事記

- 來源：破境、換 Era、建築首次建成、宗門、奇遇重大結果、壽元丹、輪迴。
- 最多 12 則；超過時依權重取樣（破境＞奇遇＞建築＞一般）。
- 每則固定格式：年齡＋一句話＋可選的資源差異。

#### F. 抉擇簿

- 每則：年齡、來源（奇遇／境界抉擇）、選項、代價、所得。
- 只記已發生的事，不做「如果當初」模擬。
- 可依類型篩選：全部／奇遇／境界／宗門。
- 與 HUD 訊息不同：這是持久化、去重、可閱讀的紀錄。

#### G. 歷世比較（P1）

- 小 multiples：每世一根道心柱、一根道證柱；X 軸是世界數。
- 另一張：每世最高境界與享年。
- 點擊某世可看該世摘要（不一定要完整年度序列）。
- 這是 Dao2 相對 1in8b 的優勢：輪迴是核心玩法，跨世資料天然有價值。

#### H. 輪迴預覽

- 保留現有 B 總和、預期道心、預期道證、傳承比例。
- 加上「本世實際 vs 預期」對照，讓玩家理解公式。
- 按鈕仍只有一個「入定轉世」。

### 8.4 空的與壞的資料

- 舊存檔第一次開啟：顯示「此世尚未開始記錄」，不顯示 0 假圖。
- 帳簿 schema 過新：顯示「紀錄版本不支援」，停用圖表但保留輪迴。
- 部分年份缺失：人生帶留白，摘要標「紀錄不完整」。
- 沒有任何奇遇：抉擇簿顯示「此生未遇奇遇」，不隱藏區塊。

## 9. 設計提案：抉擇卡與奇遇回饋

### 9.1 現況問題

`fortune_modal.gd` 目前：

- 成本顯示原始資源 ID（例如 `lingli`），不是玩家看到的名稱。
- 獎勵完全隱藏，選項只有文字與描述。
- 選後只更新一行狀態訊息，沒有代價／所得／餘量。
- 偏好標籤（境界／天候／時辰）是工程欄位，玩家難以理解。
- 沒有寫入持久紀錄。

### 9.2 建議卡片結構

```text
【奇遇】古洞殘碑                         31 歲 · 子時
──────────────────────────────────────
你循著靈脈走入洞窟，碑上劍痕未散。

道典：此處靈氣偏「金」，金丹修士更易共鳴。

1  探入洞窟
   靈石 -20　藥草 +15　歷練 +30 秒
2  靜坐聽雨
   悟性 +90 秒（小幅）
3  取走殘碑
   靈石 +50　業障 +1（風險）
──────────────────────────────────────
[ 順勢而為 5s ]        [ 離開 ]
```

要點：

- **成本精確**：靈石 -20 就是 -20。
- **獎勵分級**：內容有實值就顯示實值；沒有就顯示「小幅／顯著」，不編造數字。
- **風險用文字**：不要只靠紅色。
- **偏好轉譯**：「道典」一句話，而不是 `realm_bias=realm_gold`。
- **事後收據**：選後在同一張卡或系統訊息顯示：

```text
代價：靈石 -20
所得：藥草 +15、歷練 +30 秒
餘量：靈石 80、藥草 42
```

並寫入 `life_ledger.decisions`。

### 9.3 自動抉擇（P2，範圍受限）

- 只在奇遇卡出現「順勢而為」，倒數 8 秒。
- 玩家點任何選項、文字或關閉即停止。
- 設定提供「本次」與「本世」兩種；不做出跨世永久自動。
- 不套用於破境、輪迴、境界抉擇、宗門建立等不可逆操作。
- 自動選擇的結果仍要顯示收據，並在報告標記「順勢」。

**風險**：Dao2 的奇遇是少數需要玩家閱讀的節點；全面自動會讓遊戲變成純掛機。若 P0／P1 的報告與收據已能提升參與，P2 可以不做。

### 9.4 道心寄語（P2）

- 破境、壽盡時，可選填 60 字內的一句話。
- 不影響數值；寫入 `journal`，在報告與下一世開場顯示。
- 需要輸入清洗（長度、換行、控制字元），且不進分享或網路。
- 若玩家不填，不阻擋流程。

## 10. 什麼不該抄

| 1in8b 做法 | 為何不適合 Dao2 |
| --- | --- |
| 每年選重心 | Dao2 的核心是背景生產與建築配置；每年跳窗會打断放置節奏 |
| 四維 0–100 數值 | Dao2 已有境界、道心、道證、資源多層；再疊四維會語意重複 |
| 172 國真實資料 | 世界觀是九界修仙，不需要現實統計 |
| 1500 條完整日誌 | 行動端閱讀負擔大；用取樣與大事記即可 |
| 分享圖卡與紀念館 | 無帳號、涉及隱私與外部服務；偏離單機核心 |
| 16 種自動性格 | 設計與測試成本高，且與 Dao2 的抉擇密度不匹配 |
| 死亡機率曲線 | Dao2 沒有這個模型；假曲線會誤導 |
| 紅色／綠色唯一編碼 | 色盲與低對比風險；必須加文字與形狀 |

## 12. 測試與驗收清單

### 12.1 規則

- [ ] 產率 2／秒、10 秒、容量 15：produced 20、overflow 5、期末 15。
- [ ] 升級消耗 30：spent 30，期末正確，不把消耗算成 produced。
- [ ] 事件同時給付與扣除：gained 與 spent 分開，淨值等於期末減期初。
- [ ] 跨年補寫：一次推進 3 年，yearly 增加 3 列，數值對應。
- [ ] 一世 80 年：yearly 不超過 80 列；Era 2 不超過 120 列。
- [ ] 封存順序：輪迴獎勵不進前世 `dao_heart_end`。
- [ ] 重複輪迴：同一世不重複封存。
- [ ] 舊存檔：缺欄位可載入；壞帳簿不阻擋遊戲。
- [ ] 存檔 roundtrip：帳簿與 `past_lives` 完全一致。
- [ ] 報告唯讀：開啟報告前後，資源、道心、道證、RNG 狀態不變。
- [ ] 不新增 RNG 呼叫：同一存檔重複產生報告，內容一致。

### 12.2 呈現

- [ ] 360×640：所有區塊單欄、可滾動、無水平溢出。
- [ ] 844×390：橫式下報告仍可操作，按鈕不被遮擋。
- [ ] 1280×720：圖表與表格對齊，數字不截斷。

### 15.2 實際畫面值得借鑑的地方

**A. 用「文件」給一生身份，再讓玩家閱讀數據。** 出生卡的大姓名、登記標頭、小型編號與欄位分組，讓同一組數值先成為某個人的處境。公開追思館則把肖像、一句人生特徵、起終地與年度縮圖放進摘要。這些層級比裝飾紋理更有價值。

DAO2 可把第一屏做成「第幾世／享年／最高修行境界／一句有依據的回顧」，旁邊保留洞府或修士小像，下方明列結算方式與傳承。姓名與題字用現有粗明體，帳目沿用資訊黑體及對齊數字；不必加入護照式英文碼、粉紅品牌色或額外等寬字型。紙色墨字與少量朱砂已足以維持 DAO2 風格。

**B. 以少量物件讓成果可辨認。** 房間中的證書、合照、寵物等，讓人物經歷具有視覺索引；相簿則把人生分成幾段，圖像配年齡與一句敘事，閱讀負擔低於連續流水帳。[實際畫面](https://1in8b.life/zh/m/wbc272dc5)支持這個模式，但物品點擊後的行走效果本輪沒有測試。

DAO2 先做報告內最多三張「此生留痕」卡：一次關鍵破境、一項有紀錄的建設成果、一件重要奇遇。沿用已有、授權清楚的建築或法器圖，點卡查看對應紀錄。這不要求新增可布置房間，也不應把象徵物直接放上島面；涉及世界地標時仍須走 docs/08 美術驗收。沒有對應事實或美術時用文字卡，不捏造戰利品。

**C. 抉擇暫收比多一層確認更有用。** 實測收起抉擇後，原本的場景、狀態及日誌重新可見，底部留有待辦入口；重新展開仍是同一個問題。這能解決玩家做決策時需要查資料、但模態卡擋住背景的矛盾。

DAO2 可在奇遇卡提供「稍後查看」：保留 pending ID、選項、成本與結果狀態，回洞府查資源後能重新開啟。暫收本身不應代表放棄、免費重抽或自動選擇。是否繼續推進時間、能否先做其他命令、會否到期，必須用 DAO2 的命令與待決規則明定；不能因參考站畫面看似暫停便推定 DAO2 核心也應暫停。

**D. 同一身份摘要配不同閱讀任務。** 寬版追思館是左摘要、右分頁；窄版則摘要在前、內容在後。相簿切換時仍知道正在看誰，這比每頁重新放一大段頭資訊有效。

DAO2 報告可分「生平／帳目／抉擇」，桌面讓簡短本世摘要與內容並列，短橫式改為緊湊摘要列加單一內容區。固定標題、關閉與分頁；只讓內容在 Godot ScrollContainer 內捲動。輪迴確認是獨立動作，不在每張圖旁重複出現。

**E. 資料縮圖適合掃讀，不適合精確選取。** 公開摘要每年幸福縮圖只有細條，在寬版側欄也能看出高低起伏；但它沒有足夠空間承載精確數字與逐年觸控。DAO2 可用縮圖表達「這一世的形狀」，精查另用可放大的圖表與年份清單。不能把每格畫得很小、再宣稱各格都符合 44px 觸控。

**F. 視覺也有不宜照搬的部分。** 實看遊戲是深色背景、青綠資訊盒及粉紅重點，公開追思館卻是暖紙色與像素房間，切換有明顯情緒轉場。DAO2 可學壽盡時降低場景動態、讓紙本報告成為焦點；沒有必要為報告另造一整套色彩與像素美術。出生卡在目前窄視圖很長，主要按鈕在下方；不能只因排版整齊就推定低摩擦。主介面工具列也較密集，DAO2 不應照搬整排控制。

### 15.3 壽盡報告：把「發生了什麼」連到「下世如何調整」

以下是 **DAO2 新提案**，不是聲稱 1in8b 已有同樣實測功能。

| 玩家問題 | 建議呈現 | 點開後的證據 |
| --- | --- | --- |
| 我這一生留下什麼？ | 第一屏的本世身份與最多三件留痕 | 對應破境、建設、奇遇紀錄 |
| 資源到底去哪裡？ | 選一種資源，顯示收入／用途橫條與期初、期末 | 建設、合成、宗門、事件等實際收支明細 |
| 何時開始卡住？ | 同齡軸的庫存／容量圖與滿倉區間 | 年齡、當時容量、截斷量與事件 |
| 選擇造成什麼？ | 事件標記與實際結果收據 | 選項、已付成本、實得、截斷與餘量 |
| 下世能試什麼？ | 最多兩條有依據的觀察 | 例如某段時間的滿倉與溢出，連回圖表；不承諾最佳策略 |

建議首版順序為：**生平摘要 → 留痕／關鍵時刻 → 帳目重點 → 輪迴保留與清除預覽**。完整年度圖、全部事件與跨世比較按需開啟。玩家不必讀完報告才能轉世，但也能先關閉報告；歷史回看與正式輪迴命令要分清。

圖表選型收斂如下：

- **首版用收支橫條與數字表**。每次只看一種資源，不直接把靈石、靈力、木材加成一個總產值；不同單位沒有共同價值標準。消耗不是壞事，應用中性色加用途標籤，朱砂留給不足／風險；正負號與文字不能省略。
- **再做庫存與容量的同軸圖**。X 軸為本世年齡，Y 軸明示資源與單位；容量用不同線型，破境／奇遇用標記與可點列表。收入、產率與庫存分開顯示，避免拿每秒產出與累積庫存畫成同單位曲線。
- **溢出需獨立標示**。滿倉後被截斷的產出不屬於已入庫收入，也不是一般消耗。不以淡色覆蓋一層就省略定義。高溢出表示某段時間容量或使用不足，不能單憑總量診斷整世瓶頸。
- **預設不做 Sankey／圓餅／跨資源總榜**。首版沒有完整來源去向資料，流向圖會暗示不存在的精確追蹤。大量不同尺度的大數也不適合共用線性軸；若日後採對數／比例視圖，必須明示尺度與零值處理。
- **事件在圖上對齊，不編造因果**。可說某次奇遇實得多少、某次建設當下產率變化；不能只見曲線上升就寫成事件增加了全世百分之多少。沒有反事實模擬就不產生「當初換個選項能多賺多少」。

### 15.4 原提案必須更正的事項

本節是後續實作依據；上方舊草案、示例數字及勾選清單不得直接當測試契約。

1. **壽命不是每世固定 80／120 列。** `src/simulation/lifespan.gd:max_lifespan_seconds` 會累加各境界壽命，再套天賦與丹藥。因此現有 Era 1 的 80 與 Era 2 的 120，在無加成 Era 2 合為 **200 年**。突破不重設年齡；不能截去第 121–200 年。年度資料預算須與顯示格數分開，超長人生採分段聚合或多層解析度，仍保留里程碑。
2. **年度快照不能拿結算終值回填每年。** 一次推進三年後只有終點，不足以知道各年底庫存；應在核心推進遇到年度邊界時採樣，或記錄足以重建的分段資料。若只有區間統計，明示區間與解析度，不假裝逐年實測。同一序列切小段或整段結算的帳簿須可核對。
3. **資源淨差不能拆出同交易的收與支。** 同一指令先扣 20 再得 30，前後只會看見 +10。採用已提交的結構化交易記錄，分開 gross inflow、outflow、overflow 與容量變更等 adjustment；淨差只作對帳。呈現層不寫帳；GameSession、離線與輪迴路徑共用權威記錄，避免雙記。
4. **TimeAdvancer 目前沒有可直接持久化的溢出帳。** 程式做上限 clamp，但回傳未附逐資源 overflow 明細；第 5 節「計算溢出」不能理解成已有帳簿資料。未來也要區分容量縮減造成的截斷、一般生產溢出與事件獎勵滿倉。
5. **先定義再驗算。** 若 produced 是截斷前生產，期末應為「期初＋produced＋事件收入－支出－溢出＋其他調整」。例如期初 0、生產 12430、事件 310、支出 9880、溢出 210，期末為 **2650**、淨變化 **+2650**；舊模型的 2550 與示意圖的 +2340 不一致。若採實際入庫收入，則溢出只作旁列，不再扣第二次。
6. **抉擇效果不能一概說已透明。** 實看兩歲抉擇只有行為敘述；選後是決定與敘事兩行。6 歲後的年度重心才看到狀態方向提示。因此「成本／實得／餘量」是 DAO2 應加的功能，本輪沒有證明參考站每種抉擇都有它。未知隨機結果顯示定性風險；顯示獎勵時分清標稱與容量限制後的實得。
7. **界域不是修行境界。** 原文把 `realm_bias` 解釋成金丹偏好不正確；`fortune_modal.gd` 實際分別顯示界域、天候、時辰。DAO2 道典應按欄位與真實觸發原因翻譯；「契合條件」也不等於「本次確由該條件觸發」。修行境界用 era_id，九界法則用 realm_id。
8. **直式遵守旋轉提示。** docs/07 的 2026-09-30 核定決策優先於其下歷史直式完整排版敘述。REPORT-1 的正式驗收應是 1280×720 與 844×390 橫式內容可讀可操作，360×640 驗旋轉提示及回到橫式後狀態；不額外承諾直式完整報告。
