# 築基體驗診斷計畫

任務 `ERA2-PLAYTEST-PLAN`。現有證據用於排出試玩順序，第一輪實際試玩與根因判定屬 `ERA2-PLAYTEST-R1`。沿用 [前期流程](17-early-progression-and-onboarding-plan.md) 與 [UI／UX 規範](19-ui-ux-guidelines.md)。

## 第一輪怎麼玩

使用同一份 [ECON-R1-F 候選包](economy/econ-r1-f-contract.md)、桌面 Chrome 1280×720 滑鼠。分別記錄入口、候選包指紋、存檔來源與初始境界／層數。先做玩家回饋所屬版本。如果版本未知，先以新版 `?edition=econ-r1` 走短段，預設版只用來對照共同的開島、貨運和加工操作。兩版使用各自合法的隔離存檔與瀏覽器來源。

本機可執行 `python tools/web_static_server.py --port 4182 --directory build/econ-r1-f-web`，以隔離 Chrome profile 開啟 `http://127.0.0.1:4182/index.html?edition=econ-r1`。若 4182 已占用，選用空閒埠並記下來源。已有進度的日常瀏覽器 profile 保留原樣。

從剛築基、未開始經營的可追溯同版存檔起步。優先用正常命令賺得的進度。若只有資助檔，記下預給的資源與建築，只用於找路、點擊和流程比較。第一段做至祖島取得第一份銅精，最多觀察 15 分鐘。上限用來定位卡點，並作為續玩停點。新版第一段結束後，另用同版築基五層檢查點，觀察第一次需要 R03 的升層阻擋。

| 觀察點 | 給試玩者的目標 | 記錄 |
|---|---|---|
| 進入築基 | 找到此刻最值得做的一件事 | 玩家先去哪個入口，能否說出接下來要做什麼，是否把宗門或技能誤當必做 |
| 首次開島到加工 | 取得第一份銅精 | 最早停住的畫面，是否懂得區分玄礦地方庫存、在途與祖島可用量，是否能從缺料／研習捷徑回到原配方 |
| 築基五層 | 找出下一次升層所需條件 | 是否知道先補 R03 還是先補材料，補齊後能否回原升層入口；材料足夠時仍要走過哪些前置 |

每個點先讓玩家自己找路。卡住時保留當下畫面與原話，再只補一句「缺什麼、在哪做、做完回哪」。記提示前後的第一個成功操作、錯誤入口／返回次數，以及這三段時間：找路／操作、等待中仍可推進其他目標、沒有有效下一步的空等。提示前後有資源到貨或工作完工時，從隔離檢查點重播再比較。已知路線的 Codex 操作與人類首次體驗分開記錄。

## 如何判讀

| 類別 | 目前依據與待驗假設 | 用什麼區分 |
|---|---|---|
| 介面／引導 | 舊版已核定玄礦先行與缺料後續接配方。新版另外有工藝研習與工坊。E 階段的資助檔已實點「製造 → 開拓 → 研習」，因此優先看玩家能否自行發現這條路及回到原配方。[UI 規範](19-ui-ux-guidelines.md) · [E 階段證據](development-status.md#econ-r1-e) | 只加提示就順利繼續，優先檢查入口文案、當前缺口與返回狀態。 |
| 數值節奏 | 新版 R01／R02／R03 的基礎工時為 120／180／300 秒，依序佔用同一研習槽。這 600 秒是基礎研習工時加總，部分可和修行、採集或物流重疊。[研究資料](../content/research/econ_r1.json) · [C 契約](economy/econ-r1-c-contract.md) | 玩家知道做法，仍在關鍵路徑上被報價、產率、運程或工時卡住。用正式 View／報價與自然時間核對實際空等。 |
| 系統設計 | 新版首份銅精串起 R01、工坊、玄礦／回運與 R02。築基五層起升層另需 R03，R03 又消耗靈材與銅精。首段先看這些交接是否教會玩家一個可重用循環。[C 契約](economy/econ-r1-c-contract.md) · [規則閘門](../src/economy/economy_slice.gd) | 提示充分且用同版資助檔降低材料壓力後，玩家仍得重複走沒有新決策的必經步驟，才提高結構問題的優先級。 |

如果畫面說可做但命令拒絕、重載改變結果或滑鼠未命中，另記為待重現缺陷。若「不流暢」是掉幀或操作延遲，另記瀏覽器與發生操作，走專案效能驗證。第一輪整理依據不足的項目標「待驗」，可保留共因。

既有 D2 賺得軌跡可當規則對照。單一散修控制器在模擬第 1,347 秒築基、第 1,687 秒提交首批銅精、第 1,707 秒開始 R03，相對築基為 340／360 秒。這組數字只記該策略的正式命令時點，首批提交與實際完工分開，人工尋路與空等另量。[D2 原始軌跡](economy/econ-r1-d2/earned-path.json)

## 第一輪紀錄與交付

可直接記錄「版本／境界層數／我想做什麼／我點了哪裡／畫面怎麼回應／我卡了多久」。保留原話；有畫面時附一張截圖。整理時用 `$dao2-playtest-review` 給出最早卡點、主因與共因、信心及下一個單變因對照。用 `$dao2-evidence-review` 核對哪些已有功能證據、哪些仍缺玩家路徑。原始本機試玩資料放 `.test-output/era2-playtest/`，採既有狀態頁記結果。

R1 交付至少一條實際操作軌跡或一個可重現的提前卡點，清楚分列自然時間、資助檔、加速模擬和人類原話。用現有候選包、既有 runner 證據與有界 Chrome 操作開始。若之後修改，再按影響跑 L1／L2。新版調參時同步更新 [F 凍結清單](../tests/fixtures/econ_r1_f/tuning-freeze.json)；若涉及前置、資源消費或可保存狀態，另列受影響的 UI、規則、資料、保存與 runner。
