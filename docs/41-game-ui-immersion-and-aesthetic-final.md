## 一、結論與視覺定位

**建議採「清雅仙家手卷」：以空島世界建立沉浸感，以紙墨、青玉、圖印建立操作語言，以少量關鍵演出建立修行的分量。**

這次升級的核心是統一視覺層級、減少重複框線與資訊噪音、讓操作具有物件感。材質、動態與光效應服務這三個目標；增加特效數量本身不作為品質指標。

洞府應讓玩家先看見修士、島體與修行狀態；工作頁應先看見本次操作的對象、成本、結果及動作；機緣與輪迴應保留閱讀節奏和敘事留白。三類畫面共享材質與操作規則，但不必長得一樣。

## 三、統一美術語言

### 3.1 材質：一個主底、少量重點

- **主底為淡紙／絹面**：正文區低對比紋理，邊緣保留纖維或舊紙細節。避免在每張卡、每個子欄、每個數值外再套一層卷軸。
- **青玉為狀態與選中**：延續既有青玉選中及就緒色；不用大片飽和玉綠遮蓋插圖。
- **朱砂為少數關鍵操作或警示**：延續既有語意，不把普通操作全部改成紅印。
- **金色為稀少的成就與突破重點**：高境界不等於每頁金邊、每卡發光；重要程度先用位置、比例、明暗建立。
- **墨色為文字與結構**：分隔線、短題簽與局部印記取代多餘框線；重要狀態保留文字／圖示，不能只靠顏色。

首批只精修一套紙面、青玉狀態、朱砂重點及其必要狀態，不同時製作3～5套彼此競爭的材質家族。九宮格切線、內容內距及裝飾安全區一併交付；既有卷軸上下安全間距保持。

### 3.2 字型與插圖

沿用 UiTypography：數字與操作黑體；敘事依已核定範圍使用文楷，卷末題名／題簽沿真實明體字重。一般正文／資料最低16px，已指定18px的敘事區保持18px，不用書法字替代所有資訊。

淡底透明插圖繼續使用已接受 B 細邊＋柔影及 UiIllustration 的小圖、自帶框例外。保留原圖，不重新烘焙陰影、不全批重畫。新圖須有用途、來源、提示詞、切層、授權及狀態紀錄；文字由 Godot 排版，不畫進圖片。

### 3.3 圖像操作

既有「圖印＋文字」為通用預設；圖意明確的徽章、物件可直接點擊；少數重點動作使用較完整印章。圖像要對應動作或物品，不能只在舊按鈕旁貼裝飾。

常態即可辨識可操作性；hover、鍵盤焦點、按下、禁用、可領、已領各有清楚差異。禁用原因保留可讀入口。倒數獨立於動作名稱，讀正式 View，缺總時長時不繪假進度；保存失敗與「尚未完成動作」必須區分。

## 四、三類畫面的具體方向

| 畫面 | 保留 | 改善重點 | 避免 |
| --- | --- | --- | --- |
| 洞府／世界 | 已接受分層島體、修士、地標、真實貨運及共用 HUD | 讓人物與地標成為第一視線；降低次要外框對比；資源依既有偏好顯示；通知只提示可處理事件 | 滿四角裝飾、常駐文字牌、沒有實際用途的飛劍與光線 |
| 營造／製造／煉丹／運輸 | 容器、單工作區、材料來源／可用／需求、真實進度 | 明確的「對象→材料／狀態→動作」；放大主要插圖的辨識度，減少重複頁題與巢狀框；長細節留原詳情入口 | 為美術藏成本、把地方與祖島庫存混成總數、縮字換空間 |
| 機緣／成就／輪迴 | 已接受圖印、徽章直領、卷末字型及固定確認區 | 機緣突出情境與選項；成就突出徽章及領訖；輪迴突出一生題名與敘事，帳目保持可查 | 每句飄字、每次翻頁消融、將相同卷軸重複嵌套 |

採非對稱視覺重心，但布局仍由 anchors／containers 負責。寬式沿共用殼條件，短橫式優先保留正文、44px動作與固定保存區；不得以瀏覽器捲軸、裁切、固定座標或改小字級規避。

## 五、微動態、聲音與特效

以下時間是**待樣張調整的起始建議值**，不是已核定的硬規格。

| 層級 | 建議行為 | 起始參數／限制 |
| --- | --- | --- |
| 日常 Hover／焦點 | 亮邊、墨線或局部圖印明暗 | 約80～120ms；分頁、資料列不彈跳 |
| 按下 | 圖印局部壓暗或輕微下沉 | 約60～100ms；固定實際命中區，不縮整個容器 |
| 一般彈窗／抽屜 | 短淡入或輕位移 | 約140～200ms；避免彈性回擺；連續切換可中止前次動畫 |
| 完成／領取 | 局部亮起、領訖印、簡短回饋 | 約200～400ms一次；同批事件合併，普通自動產出不逐筆飄字 |
| 突破／輪迴 | 沿既有正式結果演出專項精修 | 另案核對可跳過、重播與保存保護；演出不決定結果 |

動畫只作用於呈現子節點，不連續改容器最小尺寸，不讓文字及點擊區隨縮放飄移。快速開關、切頁、縮放視窗時中止舊 Tween，恢復正確最終狀態；覆層回呼沿既有 token／route 管理，避免關閉動畫完成後誤關新頁。

聲音以短紙聲、印章或玉器輕響建立一致回饋，日常操作低強度，重要完成較明確；不為每次 hover 播音，同批限制重疊。沿現有音量／靜音與 Web 使用者手勢啟動，素材來源需紀錄。

Shader 優先做小面積、短時間的光邊與印記浮現；水墨消融可留給少數章節或大事件候選，不用於高頻分頁。全螢幕 screen-reading 模糊、持續熱擾動及全面 Bloom 不列首批必要項，不因使用引擎就假定效果免費或所有平台一致。

低特效／低動態保留靜態可領標記、焦點與結果文字；停用呼吸、掃光、粒子及裝飾轉場。隱藏頁與離屏裝飾停止更新。首批試點同畫面最多保留一個主動態焦點，待實際觀感與效能結果再調整。

## 七、驗收與效能邊界

1. **美術驗收**：同一狀態的前後對照中，玩家能指出主要對象、當前狀態、下一動作；正文不受紋理干擾，裝飾不遮成本與按鈕。美術接受須由使用者確認，程式測試不能代替。
2. **互動驗收**：hover／鍵盤焦點／按下／禁用／就緒／已完成可辨識；連續點擊只送合法命令；動畫中關閉、返回與尺寸變更無殘影遮罩或錯誤焦點。正式命令與保存重試沿既有契約。
3. **分級驗收**：每子階段先 `-Only '精確selector' -List`，L1限受影響1～5支及1280×720；共用核心相依確需更多時列明理由採L2。功能完成合併一次含新修改的1280×720桌面Web滑鼠抽驗。只有整批收尾／交付候選才做一次L3全runner、全矩陣、Web匯出壓縮與三橫式。
4. **效能驗收**：增加持續動態或Shader的階段，對相同資料／環境做針對性前後比較；常態目標60FPS，≥55FPS時間達80%以上，最後10秒高於30FPS，檢查持續劣化。低動態關閉後不得繼續留下相同動畫負擔。不將既有140支通過當作新視覺效能證據。
5. **已知界線**：既有長時WebGL RangeError尚未修復；若在本次驗收中發生，依實際失敗定位，不用外觀完成掩蓋。冷啟動≤10秒沿政策暫緩常態阻擋，觸控與實機延期、非當前阻擋，不列下一步必做。
6. **交付檢查**：採既有 `tools/delivery_check.py` 與 Git diff；不新增專屬closure／audit腳本。測試輸出沿`.test-output/`與guard，使用隔離進度，不覆寫玩家存檔。
