# 資源圖像化檢查：IMM-0 R3

2026-10-27，依使用者指出製造左側純文字資源區所做的來源檢查。涵蓋共用殼的十三個功能路由、資源抽屜及相關材料詳情；這是程式接線檢查，並非十三頁本輪全都完成實際滑鼠驗收。

2026-10-27後續：使用者已接受R3相關原則並要求延伸完整介面。本檢查表轉為正式遷移清單，批次與完成條件見[docs43](43-full-ui-adjustment-plan.md)；下述正式來源仍未接入，檢查發現不等於已修復。

## 根因

`ui_shell_resources.gd` 將結構化 View 數值轉成 `details` 長字串；`ui_shell_controller.gd` 建立單一 `context_text: Label` 並把字串填入。製造的「名稱／可用／預留／容量」因此逐筆堆成三行。相同元件同時承接其他頁，單改配方卡無法消除這個問題。

來源：[字串生成](../src/presentation/ui_shell_resources.gd)（16–46、47–81行）、[共用顯示](../src/presentation/ui_shell_controller.gd)（123–128、313–316行）、[路由顯示政策](../src/presentation/ui_shell_policy.gd)（INVENTORY_ROUTES／FOCUSED_ROUTES與resolve）。正式接線仍是原狀；新樣張使用獨立圖像庫存元件，不把樣張當作已修正正式九頁。

## 十三頁檢查表

| 功能頁 | 同類資源文字呈現 | 判定／後續處理 |
| --- | --- | --- |
| 洞府建築 | 走原resource_ribbon；建築資源列已有圖示 | 不屬於這個共用長字串問題。 |
| 空島 | 同一context_text，寬式左欄／短式庫存抽屜 | 與製造同根因，優先套同一圖像庫存；R3有原生示例。 |
| 製造 | 同一context_text，寬式左欄／短式庫存抽屜 | 本輪修訂對象；配方設定內另有文字庫存詳情，需另處理。 |
| 運輸 | 同一context_text；可依選定航線列兩端庫存 | 與製造同根因；R3有原生示例。來源、目的與在途不可混為總庫存。 |
| 技能 | 共用資源抽屜只列技能點 | 屬同一文字元件，但只有單一貨幣；可改圖印數量，不等同多行倉庫的嚴重程度。 |
| 煉丹 | 原resource_ribbon有圖；配方材料已圖像化 | 不屬於這個共用長字串問題；格形統一另依已核定方向。 |
| 靈獸 | 共用資源抽屜以文字列餵養成本及獸魂 | 同一文字元件的另一用途；改成食物ICON與獸魂圖印，避免把獸魂當一般倉庫材料。 |
| 成就 | 本路由無共用資源區；徽章本來已有圖 | 未發現這個同類資源欄。 |
| 輪迴／天賦 | 天賦資源抽屜以文字列道心／道證 | 同一元件、雙貨幣；可用圖印數量，保留各自單位，不影響卷末敘事。 |
| 九界 | 無此共用庫存欄 | 本路由不屬於問題；舊靈界據點材料另列下表。 |
| 宗門 | 功法／坊市寬式左欄列整份資源文字，其他子頁抽屜列貢獻 | 多資源欄與製造同類；貢獻及材料分組，功法／坊市卡成本亦需清理。 |
| 機緣 | 有實際成本才開共用資源入口，抽屜內為文字成本列 | 主頁依使用者決策保留原版；只列共用抽屜同類問題，不重新改主頁布局。 |
| 天道決策 | 共用資源抽屜以文字列法令相關材料 | 抽屜有同類問題；主頁成本已使用ResourceIcon，不能誤稱整頁只有文字。 |

共用 `context_text` 可承接 **9個功能路由**；其中空島／製造／運輸／宗門（功法、坊市）會形成與截圖相近的多筆常駐資源欄，其餘依抽屜及成本條件顯示。建築、煉丹已有圖像資源列，成就、九界沒有該共用庫存入口。

| 位置 | 程式依據 | 調整方向 |

不列為同類缺陷：`building_catalog.resource_summary` 雖仍生成字串，但未掛入顯示樹；空島 `local_stock.tooltip_text` 的逐行文字只是既有圖格提示；帳目、歷世數值表、收據、說明與敘事以文字閱讀本就合理。不能以搜尋到join或多行Label就判定UI不合格。

## 共用呈現方向

庫存主區用正方形物品ICON＋右下可用量，依島別分組；名稱、容量、預留及來源透過TIP／選中詳情查看。選中區可保留一份帶物品圖的名稱與可用／容量，以及有真實數值的細容量條；不用每項重複三行標籤。非零容量預留有靜態提示，實際在途另組，零貨物不塞滿清單。未知／缺圖物品需可辨識的字印或名稱，不能只剩數字。

R3僅替換樣張中的情境資源區，沿用正式View讀數、來源島、容量預留、庫存抽屜與共用關閉流程；正式遷移應集中替換共用文字元件，然後分批處理上述成本詳情，而不是每頁建立不同風格的資源欄。
