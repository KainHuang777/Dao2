## 1. 任務範圍與現況

總任務 `SECT-REFORM`；本輪 `SECT-REFORM-PLAN` 為文件階段，下一階段 `SECT-REFORM-DESIGN`。

本次使用者明確插入宗門改版準備，優先整理其設計；不宣告原 `ERA2-HUB-ECONOMY` 剩餘失敗已修復，不自動開始下一大型實作。來源以本機正式程式為準，不依歷史文件的內容數量推定。

| 項目 | 2026-10-30 靜態核對基線 | 核定改版方向 |
| --- | --- | --- |
| 入宗 | 第一世練氣只預覽；Era≥2 或輪迴≥1次可加入 | 保持基本資格，不以輪迴次數把五宗排成高低階 |
| 五宗 | 名稱／圖／文案不同；共用8功法、30模板、8商品 | 共通基礎＋各宗專屬功法，形成平行路線 |
| 輪迴 | 退宗、清派遣與候選；功法、貢獻、購買次數保留 | 傳承跨世保存；當世所屬宗門決定專屬效果啟用 |
| 成就／天賦 | 已有跨世成就、道心天賦；尚無各宗有效輪迴世數計數 | 各宗成就揭露隱藏天賦購買資格 |

| 靈獸名額 | 每世一獸，不能放生／更換；成熟輪迴給同種獸魂 | 隨機發現不得自動占用名額；沿用養成主體 |

## 2. 已核定：五宗平行專精

| 宗門 | 定位 | 專屬功法設計軸 |
| --- | --- | --- |
| 太虛天闕 | 吐納與修煉 | 境界進度 |
| 天劍聖宗 | 礦材與煉器加工 | 產業材料供給；不假設已有戰鬥系統 |
| 縹緲仙宮 | 藥草與煉丹 | 丹藥使用、材料節省 |
| 萬佛靈宗 | 養生與延壽 | 當世經營時間 |
| 紫霄玄門 | 陣法、聚靈與容量 | 庫容、突破準備 |

- 保留共通基礎功法，特色加成主要經專屬功法逐步取得，不僅換名，也不一次免費疊滿所有加成。
- 高階傳承依當世境界與該宗修習進度開放；五宗不採「輪迴越多才能加入更強宗門」的階級替代。
- 每世可重新選宗；已學傳承保留，但專屬功法／宗門傳承天賦只在當世加入對應宗門時啟用。共通功法沿逐項相容表處理，不能一概把舊功法退宗後的既有效果取消。
- 比較修速、壽元、容量與供給的間接收益，避免某宗全面勝出；不把不同材料直接折成虛構通用價值。
- 現有8項功法逐項分類、舊投入補償／轉換方案、正式宗門ID與獸種配置交由 DESIGN 定表。現行 `sect_id` 預設 `taixu_sect`，加入只改 `sect_name`；不可直接用此預設ID歸屬所有舊玩家。

## 3. 已核定：各宗輪迴成就與隱藏傳承天賦

記錄每宗「有效完成並輪迴的世數」，不是總輪迴次數、點擊入宗次數或連續登入天數。每世只歸屬一宗、只計一次，在正式成功輪迴交易中、清除當世身分前結算。

| 候選門檻 | 獎勵方向 |
| --- | --- |
| 該宗1世 | 初階成就，揭露對應隱藏傳承天賦 |
| 該宗3世 | 進階成就，開放後續天賦階數 |
| 該宗5世 | 圓滿成就，開放最終階數／稱號 |
| 五宗各1世 | 「五宗問道」綜合成就 |

**1／3／5、築基且完成3次委託才算有效世，皆為已接受方案中的候選數字，需依輪迴節奏定案；不當作已上線門檻。** 委託進度必須是該世正式領取，不用跨世總數冒充。高階傳承的其他修習要求、綜合成就實際獎勵仍待定。

- 達成條件揭露天賦購買資格，仍須花道心學習；永久保存解鎖與已學階數，專屬效果依當世所屬宗門啟用，五條不得同時變成全域加成。
- 首次揭露後可讀後續條件與目前進度；隱藏只保留發現感，不阻礙長期規劃。
- DESIGN 定明資格解鎖與成就領獎的關係，避免領獎順序影響可學資格；領獎、學習均沿原子命令與去重收據。
- 新增每世有效進度與跨世累計；舊檔不把總輪迴數平均／全部塞入某宗。預設從更新後累積，只有可驗證且能去重的歷史才可補登，無法確認的歷史不虛構。

## 4. 已核定：宗門守護獸與可保底的發現流程

「專屬守護獸」指宗門代表獸及取得加權，**不是其他宗門完全不能取得**。2026-10-30使用者後續明確選擇「五宗各有不同的新獸，接受較多美術與內容工作」；此選擇取代PLAN原先保留獸種數量、DESIGN首稿一家族五契相的候選。正式方向為五獨立新獸，現有六獸保留，細項見[DESIGN第二稿§5](47-sect-reform-numeric-design.md#sect-guardian-species)。名字／造型與新倍率仍待核定，不以此選擇聲稱素材已接受。

1. 合資格宗門委託可發現靈獸，生成時凍結該實例獎勵；完成並領取後獲得可保存的結契資格。
2. 玩家自行選擇已取得資格的靈獸結契；發現不自動結契、不替換現有獸，不占唯一名額。
3. 同宗提高合資格代表獸抽取權重；另累積信物，可指定兌換目標，避免一世全靠運氣。
4. 世數、功法、當世境界、開島／餵料供給不能互相混用。資格券不繞過結契境界及必要供給條件。

目前定義：靈狐Era3、玄龜／霜角鹿Era4、銜芝鶴Era5、火鳳Era6、雲蛟Era8；雲蛟尚不能算 Era1–6 正常可達。五宗首次取得優勢需在相近階段可體驗，不能以Era8獸作某宗唯一優勢。高階神獸可作後續傳承目標，不能藉本案跳開Era7–8供給。

DESIGN 必須完成：

- 五宗獸種對應與功法組合比較；使用者已明確授權五種新獸與增加美術／內容工作，需逐獸列獨立ID、獸魂／天賦、成長素材與驗收量，不再回到是否新增五獸的方向選擇。
- 分開定義任務品階率、發現事件率、條件獸池權重與總取得機率；列出每階段池中合資格數。只有一種合格獸時，加權可能沒有額外收益，必須明示。
- 信物來源、指定兌換成本、合理最壞等待、重複發現轉換、持獸後仍能否取得資格、資格與信物是否跨世保留、上限及滿額行為。
- 現有「直接免費結契」哪些改為資格制、哪些保留作新手保底，以及已達資格／已持獸／既有獸魂天賦的遷移。不允許一邊保留同獸無條件免費取得，一邊宣稱它的掉率提供稀有價值。
- 守護獸資格和信物不是獸魂；成熟輪迴獸魂結算沿既有契約，任何額外產魂需另列規則，不重複發獎。
- 新增抽選使用正式可保存RNG狀態；未啟用core_save的歷史路徑仍使用global `randi()`；CORE-SAVE啟用後，宗門任務使用`sect.rng.version=1`的獨立SeededRandom流。重載、切頁、保存拒寫／重試不能重抽或重發；必要時以新內容版本明示未來抽樣變動。

## 5. 與升階稀有物的邊界

本次明確核定的是五宗差異、成就傳承與守護獸方案。前輪提出的「宗門貢獻兌換突破信物／傳承材料」保留為獨立待設計項，不直接把目前產業材料改成宗門獨占。

現行金丹九升十符咒可自製；元嬰寒鐵、化神千年草由產地供給；煉虛化神丹可自製。若後續新增突破信物，必須五宗皆可取得且有穩定兌換，不以隨機稀有委託作唯一主線門檻；日常修行仍由空島、加工、運輸支持。

## 7. 實作契約與驗收案例

- 規則／狀態不依賴Node、貼圖、動畫或畫面RNG；UI送命令讀View，不直接改貢獻／資格／信物。新增命令需核對Session白名單、receipt與保存協調。
- 保存包含正式schema／sect／talent／beast等實際需要的版本、遷移驗證、候選提交、故障復原、拒寫重試；不在規劃階段硬指定未稽核的版本號。宗門名稱與穩定ID明確映射，不能使用預設ID推斷所有歷史。
- 驗：五宗效果互斥／共通保留、未入宗／境界不足、新世重新入宗、當世委託計數與輪迴去重、成就揭露／領獎／道心購買與跨世恢復。
- 驗：獸池資格、權重邊界、指定兌換與不足／上限拒絕、已有獸仍不被強制替換、重複資格、滿倉／滿額、生成後資格變動的凍結獎勵政策、保存重載及拒寫重試不重抽／不重扣。
- 受影響核心／保存／成就／宗門／靈獸／天賦相依runner按L1精選；先 `-Only '完整檔名或關鍵字' -List`，超過5支說明相依並按L2，不逐段跑Full或匯出候選包。
- UI遵守 [共用UI規範](19-ui-ux-guidelines.md)、[響應式規格](07-responsive-ui-web-spec.md) 與既有GameTab／CloseSeal／UiTypography／44px命中。未核定新的共用視覺通則，不另創頁面樣式；新圖保留來源、prompt、切層及授權，需美術接受。
- 觸控／實體裝置依2026-10-17指令延期、非當前阻擋；不把CLI稱為真實滑鼠驗收，不宣稱任意大數或舊存檔全相容。

PLAN及DESIGN文件階段不改正式規則、數值、保存、素材或Web包；不需要引擎測試／Web匯出。[DESIGN逐項稿](47-sect-reform-numeric-design.md)已交付，沿本文件承接已核定方向；使用者2026-10-30已指示接續CORE，以第二稿CORE參數作基準；BEAST細項及美術接受另記，不重問相同玩法方向。
