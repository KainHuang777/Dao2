# M2-D：Realm Grinder 參考主介面重構

2026-09-25。狀態：Godot 主要版型與操作已實作，Web／手機視覺待驗收。承接使用者最新兩張截圖；目前保留 docs/09 雙狀態並同步更新 docs/07。

修訂記錄（同日，優先於以下初版草圖）：使用者提供的 1920×902 畫面顯示頂部橫向資源列越框，且大量空白；因此改為左側「關閉／數量／完整」三態縱向資源簿，預設數量，滿倉變色，內容獨立捲動。右側營造簿刪除標準密度與常態成本行，統一 48 高可點列＋底部需求進度條；點列才看用途／費用。底部「空島／營造」分頁公開了兩種常態版型的切換。以下橫向資源列、72–88 高建築列與成本常駐均屬被取代的原提案，非目前實作。

## 參考與問題

參考：[官方 Steam 頁](https://store.steampowered.com/app/610080/Realm_Grinder/)、[桌面畫面](https://gfn.ru/en/games/realm-grinder/)、[補充直式畫面](https://minireview.io/incremental/realm-grinder)。這是公開畫面研究，未進行 Realm Grinder 實際遊玩。

Realm Grinder 桌面參考把場景、功能導航、施法與建築購買分區，資源讀數集中，建築採規律重複列。DAO2 借鑑固定分工、整齊數值與直接經營操作；以下布局是針對 DAO2 多資源／容量的設計判斷，不照搬素材或經濟。

目前截圖的問題：資源卡兼採集按鈕，資訊與動作不易區分；資源和洞府核心只有小標分隔；進詳情突然放大標題、敘事與按鈕；同一黑底嵌入大量矩形與空白。程式的資源 15、分組 17/20、列表 16/19、詳情 23/28、通用按鈕 24 等字級加劇失序。「下一步」已獲使用者肯定，應保留。

## 建議桌面布局

```text
┌ 修行身份：境界／層數・修煉・壽元 ─────────────────┐
│ 資源列：靈氣 庫存/容量 +每秒 │ 金錢 │ 靈木 │ 其餘   │
├─────────────────────────┬──────────────────────┤
│                         │ 營造簿          [收起]│
│      可操作的空島       │ 下一步：茅屋升至 2 階 │
│                         │ [全部] [生產] [倉儲] │
│                         │ 圖示 名稱／等級       │
│                         │      產出       [升級]│
│                         │      費用／缺料       │
│                         │ ─ 建築列獨立捲動 ──  │
│ [引氣] [採集：靈木]     │ 選取列展開效果與成本  │
├─────────────────────────┴──────────────────────┤
│ 洞府／營造          神識／歸家              更多   │
└────────────────────────────────────────────────┘
```

- 身份與資源固定於上方，選建築不改位置。資源圖示配文字、庫存／容量與淨產率；讀數不觸發採集，點擊只開來源／用途。滿倉附文字提示。
- 管理模式：空島在左，營造簿在右，桌面起始寬 360–400。大螢幕不等比例放大字體。營造簿以內容自然高度、可視區最大高度排版，只有一棟建築時不拉成整片空黑側欄。
- 空島模式：收起營造簿，保留身份及關鍵資源＋「其餘 N 項」，空島擴大。仍保留前輪的兩種常態情境。
- 下一步固定於營造簿頂部；空島模式移入身份區，只顯示一次。文字包含動詞、目標等級與条件；點擊定位／標示目標建築。長引導按需開啟，不常駐右上大訊息框。
- 採集移到世界下方動作槽，明示動詞與單次收益。引氣為起步動作，其他已解鎖資源可切換採集；資源讀數不再整格都是按鈕。
- 更多保留存檔、九界、輪迴、特效、說明；輪迴可用或存檔失敗以文字徽記提示。

上方兩列目標共 88–104 高，底列 48–56；這是起始預算，不能強行裁切。資源超過可視數量以明確入口展開；目標所需資源優先且順序穩定，不能每秒跳動重排。金錢／靈石名稱與圖示需可辨，未解鎖資源不放假讀數。

## 建築與資源分工

| 區域 | 回答的問題 | 操作 |
| --- | --- | --- |
| 資源列 | 有多少、每秒變多少、是否滿倉？ | 閱讀、查看來源／用途 |
| 建築列 | 升哪棟、花多少、增加什麼？ | 明確建造／升級鈕 |
| 下一步 | 接下來做什麼？ | 定位目標、展開引導 |
| 動作槽 | 現在能做什麼？ | 引氣／採集命令 |

建築列以 72–88 高為起點，固定圖示、名稱／等級、效果、成本和操作欄位，按鈕至少 48 高。點列主體只查看，點升級鈕才購買；桌面可直接在列表連續升級。只展開一列簡短詳情，保留列表上下文；故事描述放說明入口，先顯示當前→下一級產率／容量與費用，數值由正式規則提供。缺料寫明種類與數量，不能只變灰。

預設全部，生產／倉儲分類依內容增加顯示。下一步定位會切到目標所在分類。沒有取得命令的資源不得出現假採集入口；本次不新增批量購買或改寫經濟。

## 視覺規則

三個主要字級：22 面板標題／境界；18 建築名／主數值／操作；16 成本／產率／說明。列表與詳情共用尺度，數值按欄對齊，Amount 縮寫一致，完整值可點閱。

框體採青玉深色、古金細邊、輕微內凹資訊槽和小型圖示，避免層層圓角卡片。保留宋體風格但統一字重；先驗現有字型，必要時才引入具授權的密集正文／數字字型。新圖示需記錄來源與授權，不能複製 Realm Grinder 素材。

亮青玉表示可操作／選取，古金表示目標，暖紅配文字表示不足。容量條只表示容量，修煉條只表示修煉；沒有意義標示的綠線取消。按下、停用、聚焦、成功共用 Godot Theme。

## 手機與窄橫式

- 844×390：精簡身份／資源，管理簿約 340–360 寬，世界與動作在另一側；詳情在簿內切換，返回和主操作可達。
- 360×640：上方固定身份和資源摘要，下方以洞府／營造切換主內容；營造頁保留下一步，建築独立捲動。資源可展開，不壓成桌面三欄。
- 360×480：簡短目標和資源摘要，保留完整資訊入口；詳情正文可捲，返回與主要動作固定。不能以縮字塞入。
- Godot 點擊目標以 48×48 起步，實際 CSS 至少 44×44。觸控點明確升級鈕才執行，說明不能依賴 hover。

## 下一輪交付與驗收

任務沿用 M2-D。先製作共同 Theme、資源列與建築列的 Godot 畫面，展示新檔／多資源兩狀態；再拆開 `building_catalog.gd` 的資源、採集、列表責任，調整 `living_abode.gd` 的身份、目標及動作槽。只新增本次需要的展示元件，最後接直接升級與手機模式並同步 docs/07。

驗收：從新檔採集→建茅屋→升級→木屋→林場；只看畫面能指出庫存、產率、下一步、成本與購買入口；升級後資源／建築效果同步；詳情字級不跳變、刷新不跳捲動；多資源、長名稱、大數、缺料、滿倉、停產、壽盡可讀；五種既有尺寸無越界；真實滑鼠／手機操作不穿透世界。先驗實際畫面和操作，再以幾何 Runner 防回歸，不能用 CLI 宣稱視覺合格。

本輪已修改 `living_abode.gd`、`building_catalog.gd` 及相關 Runner：修行 HUD 與資源列固定、採集分離、桌面右側營造簿、分類、列內直接購買及展開式快速資訊。世界點茅屋仍可開完整詳情；短直式管理頁為保住建築可用高度暫收採集動作槽。新資源與建築專用圖示仍待製作及授權記錄，現階段用文字標識。實際瀏覽器畫面、滑鼠與手機觸控待驗收，M2-D 仍 IN_PROGRESS。
