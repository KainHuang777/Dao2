## 2. 入口／序章狀態機

`未揭露 → 可拜山 → 已入宗／見禮 → 已派首務 → 同門首遇 → 首報／用途介紹 → 序章完成`。

| 條件 | 呈現／命令 | 完成證據 |
| --- | --- | --- |
| 首世Era1 | 宗門主分頁、通知、引導捷徑都隱藏 | 核心仍拒絕不合資格join |
| Era2或返世 | 入口可手動用；首批供給引導完成後只邀請一次 | 沿現有供給完成旗標，不依開頁推斷 |
| 點稍後／關閉 | 不自動再搶焦點；入口保留拜山提示 | `invite_seen`，手動仍可讀 |
| 拜入 | 正常join_sect；成功後見禮可略過 | 當世sect_id；不另贈入宗資源 |
| 首務 | 推薦當前候選中合資格最短任務；沒有就提供正常刷新入口 | 成功start，或遷移時可證明的既有派遣 |
| 首遇 | 見禮及首務後提供E1；略過教學仍能手動開啟 | E1 resolve或decline，不靠動畫 |
| 首報 | 正常claim後介紹一個能負擔的現有用途；不足顯示目標成本 | 新增成功claim旗標；無強迫購買 |

供給尚未完成但玩家主動拜宗，直接承認，不重走擇宗。返世可一次「略過入門導覽」，只跳教學，不自動解故事、派遣或領獎。舊已入宗且無首次歷史的角色標記`legacy_review`，可看無獎回顧；不猜測曾否領過首次獎勵。可略過導覽不堵住任何後續日常事件（E1可獨立閱讀）。

## 4. 時間、待決與收益節制

宗齡為入宗後真正接受的模擬tick累計，1祀=60秒；暫停不走，突破不清，壽盡即停，輪迴清本世。收益上限之後仍按正式年歲時間前進，只產生待決資格，不自選、不發資源。零tick不初始化／消耗RNG。固定章節依序，最早時間不是截止時間。

單一story槽：優先序章→符合條件的下一章→日常。待決不被覆寫；生成時只抽一次模板、延遲、固定獎勵及選項版本。已占槽時不抽新候選、不累積每個錯過的時間點；解完後日常從當下排下一次，因此一次長跳和逐秒推進同終態／RNG。待決不凍結其他模擬。

大比獨立一槽：最早宗齡300秒，其後600秒一屆，`edition=1+floor((tenure-300)/600)`。空槽時提供當前最近一屆；舊未讀邀請保留，略過後跳到下一個未來屆次，不能連領錯過屆。已報名不被下一屆換掉；領取／棄賽後同樣排下一個未來屆。序章期間只安靜標示資格，不搶故事閱讀。

### 收益模型

K採普通委託下界15貢獻，均值22.5僅作參考。600秒連續普通派遣下界150、均值225（假設每60秒即時領取再派遣，候選充足，非實際玩家保證）。高稀有委託、刷新等待／玩家離線不等於此基準，不能以理論收益承諾實得。

- 日常／章節每件0～2貢獻；每個宗齡600秒epoch至多預留12故事貢獻。epoch=`floor(tenure/600)`。生成時按所有選項最大值預留；餘額不足則該件全部貨幣選項為0，UI明示「本期貢獻已滿，仍可增進交情」。未用／婉拒不退預留、不累積補領。這是透明上限，不在結算時臨時削減已承諾獎勵。
- 大比4～8名6、第三10、第二14、第一18貢獻（總額；不再額外加參與獎）。各屆最多18、每600秒最多生成一屆；無材料、獸印或永久倍率。
- 每epoch新產生負債最多12＋18=30，為下界派遣基準20%；均值基準13.33%。各名次均機率僅用敏感度參考，大比期望9，合計上界21=14%／9.33%，不宣稱玩家名次均勻。
- 領獎可延後，因此現金實收可能跨epoch集中；20%指長期生成收益率，不是任意滑動600秒現金流。單一故事＋賽事槽把未領負債限制為2＋18=20，不儲存歷屆債務。兩槽保留舊獎勵時不再生成同類新收益。
- 新收益不算正式委託領取，不加傳承有效世／守護獸保底／宗門委託成就，避免間接放大既有經濟。

初版縮小PLAN的0.2～0.5K日常提案，因六章與大比疊加後須遵20%邊界。稱號／好感不折算貢獻。五宗使用同一上限、同一大比獎表，宗門差異只改文案／策略題材，不新增某宗獨占經濟。

## 5. 大比的可重算評分

8人、3段，每段一次選擇，可關頁續做；無限時、無報名費、首版不接丹藥準備費。與7位對手競逐總分，第一版無即時戰鬥。太虛三段為「定息／辨理／問心」，另四宗只替換題材名，不用同一劍傷文案。

報名凍結：當世Era分組、level（1～10）、共通`breathing_method`有效階數＋本宗A/B當世有效階數總和（封頂10）、宗門、七對手、三段亂數、評分版本、獎表。修為基準`B=40+2*(level-1)+min(10, technique_sum)`。不讀進度比例或Amount轉float，不計傳承、獸、臨時BUFF；避免五宗容量／壽元取向天然吃虧。本宗專長對每人三段皆+3，只作題材定位，不另疊專法被動。返世Era1組的休眠專法不計有效階數。

報名可一次選「準備定息／辨理／問心」，只對該段+4，無庫存成本。每段公開選項：

| 策略 | 修正 | 已知資訊／取捨 |
| --- | --- | --- |
| 穩健 | +5 | 穩定下界 |
| 進取 | 預凍結硬幣0為-4，1為+12，各半 | 期望+4；可追分亦會掉分，先明示50%與範圍 |
| 觀察 | 該段已準備則+7，否則+2 | 準備段較強，其他段保守但較低；明示是否適用 |

每段分=`B+3+準備(0/4)+策略修正`，三段加總。進取的硬幣對三個選項共用，報名前獨立流一次抽好；不隨讀頁或選項抽樣。三NPC好感不直接加分，E6只解釋風險，避免社交成強制前置。策略故意簡單：準備段觀察最穩，其餘穩健保底／進取搏名次；不宣稱三策略在所有情況等價。

對手席位1～7：凍結level為2／3／4／5／6／7／8，technique_sum為0／1／2／3／4／5／6，依同公式得基準42／45／48／51／54／57／60。不隨玩家修為同步變強，因此進步會反映名次；這是首版固定難度譜，不宣稱完整模擬NPC修行。三段各有報名凍結偏移`-2..2`均勻整數；皆有本宗+3，固定穩健+5，其中一段按`(seat-1)%3`準備+4。名單包含三位太虛同門（席位2／4／6）＋四位生成同境修士；角色名字不代表其永久修為，屬當屆同境投影名冊，UI明示。之後其他宗切片替換熟面孔。每人總分不再擲排名亂數。

同分比較：總分高→三段分中最低段高→報名凍結的唯一tie_order小者先。tie_order為8席均勻洗牌，玩家不固定優先或吃虧；UI公開「同分先比最低段，再比當屆籤序」。名次永為1～8且無重複。名冊／每段分／名次／獎勵均能讀回重算，不能只信存下的rank。試算工具窮舉玩家27種策略×8個硬幣組合，檢查名次與選擇幅度，並非正式Godot遊戲測試。

試算結果（對手偏移0、玩家同分籤序最末）：level1／功法0可得6～8名；level5／功法5為2～7名；level10／功法10為1～2名。故首入宗不保證前三；UI須先展示組內修為與保底，不以「新手教學」暗示必勝。後期固定難度較易奪冠是本稿選擇，不另無限抬對手或擴獎；自然體感仍需後續試玩。

結算後「領取」才原子發貢獻與稱號；best_rank／稱號為小型永久記錄，重複第一不再給新貨幣獎。關頁、離線、看名次不代領；輪迴放棄未領本世賽事，不將待領塞進跨世庫存。壽盡後可讀但不可選／報名／領獎，顯示輪迴提示。

## 6. 最小狀態、版本與原子命令

候選放在`state.sect.life`，不另建全域NPC系統。內部`version=1`；正式sect/schema/rules/content版號於CORE整合時按當時最新來源分配，不在DESIGN預佔。舊版本驗證器不能接受新欄位後仍宣稱舊版相容。

| 鍵 | 上限／語義 | 輪迴 |
| --- | --- | --- |
| `version, content_version, scoring_version` | 固定白名單，內容ID≤48 UTF-8 bytes | 版本保留 |
| `life_seq, sect_id, tenure_seconds` | 序號／秒0～2147483647，宗門白名單 | 當世更新／清零 |
| `onboarding` | invite_seen／intro_seen／first_dispatch／first_claim／skip／legacy_review六bool | 清除，返世可略過 |
| `npcs` | 僅本宗3 ID，各好感0～100、首遇bool | 清除 |
| `chapter_mask, choice_flags` | 本宗6bit；6固定鍵enum（A/B/decline） | 清除 |
| `story_serial, pending_story, next_story_second` | serial有界；null或1件凍結實例 | 清除 |
| `reward_epoch, story_reserved` | epoch有界，reserved0～12 | 清除 |
| `rng` | story／tournament兩獨立非零uint32，算法版本1 | 由既有可信seed＋life_seq＋sect_id域分離建立 |
| `edition_cursor, next_invite_second, tournament` | 不倒退；null或1邀請／報名／已結算實例 | 清除 |
| `recent` | 最多4筆，固定ID／enum／tick／rank，不存全文 | 清除 |
| `memories, best_ranks` | 五宗各6bit已讀與best0～8；0=無紀錄，稱號由best推導 | 保留 |

凍結故事只存模板／內容版本、實例ID、生成tick、A/B/decline結果（貢獻整數、好感增量、enum旗標）、預留epoch；不存任意腳本文字。版本化模板檔必須保留可解舊待決的舊revision，不把舊實例套新文案或成本；找不到版本時回報可復原的不支援錯誤，不自選或換獎。

RNG沿既有SeededRandom演算法／int_range，兩流各存獨立state，不消耗舊派遣流。初始化使用穩定字串域`sect-life:1:{life_seq}:{sect_id}:story|tournament`加既有存檔seed；若原檔無可信seed，遷移候選一次建立並保存，重試重用候選值，不能每次讀檔取系統時間。報名先抽三個0／1硬幣，再按席位1～7、段1～3抽偏移，最後按固定倒序Fisher-Yates洗牌8席tie_order；此順序列為RNG版本1契約。

賽事存8席ID／凍結基準、tie_order、對手三段分／偏移、玩家三硬幣、準備段、已選策略最多3、階段／rank／獎勵、reward_claimed。最多8席，名稱字典解析，不存長小傳。非法混合狀態（如未完成三段卻claimed）拒讀；同分／分數／獎勵要重新驗算。序號到上限拒絕生成，保留既有可讀狀態，不靜默回繞。

### 6.1 時間整合與遷移

TimeAdvancer的有效一秒路徑及年歲only路徑都接同一SectLife時間helper；OfflineClosedForm有life狀態時先回共用逐秒路徑，未證明邊界等價前不寫跳步公式。helper使用本次真正接受秒數；到壽盡當秒可以累計至終點，但不再生成新故事／邀請，避免壽盡時多一個領獎窗口。線上／離線同優先序：既有時間效果→宗齡游標→生存檢查→story→tournament；UI通知晚於提交。

舊檔未入宗：加入時建life；已入宗：遷移以宗齡0起、不從年歲反推，legacy_review=true，派遣存在可證明first_dispatch，未知first_claim不推算。既有歸檔／候選遷移／讀回驗證／提交失敗重試沿現流程，舊貢獻／功法／guardians／歷史身份不動。待決凍結的RNG與生成預留包含在同一候選，保存失敗重試不能重抽。輪迴先沿原結算當世委託傳承，再清life本世鍵並保留小型永久紀錄，不把故事當派遣。

### 6.2 32KB容量預算

設計預算：既有sect最多22528 bytes，life最多8192，餘量2048，合計32768。這是實作准入預算，不是既有最壞存檔已量測的事實。工具生成有界最大鍵值／三選項／八名冊／四recent／五宗meta的合成life，量測UTF-8緊湊JSON；不含對話全文，不證明Godot編碼與全部舊存檔上界。

CORE-SAVE必須把既有四凍結委託最壞長字串／全部功法／傳承／獸許可與life滿載合併量測；若超限，先減冗餘或recent數，不刪舊任務、不截貢獻、不提高32768上限。既有合法sect已超22528時不能直接加入life導致拒讀，應保留舊進度並顯示功能尚不可啟用，直到有經證明的緊湊表示；不得誤報遷移成功。這是CORE實作門檻，非設計文件已驗證相容。
