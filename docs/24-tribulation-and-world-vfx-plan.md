# VFX-TRIB：渡劫與世界視覺提升計畫

2026-10-18。`VFX-TRIB-PLAN` 規劃交付 DONE；TRIB-0 已於同日後續完成，其餘實作 TODO。使用者指定承接 UIX-R7-F5 經驗，優先規劃渡劫核心體驗。本輪只作來源盤點與設計，不代表新美術、Shader、音效或正式演出已通過。

## 1. 設計主張

渡劫要讓人感受到「天地施壓，修士承受，心境動搖，最後付出代價或跨越境界」。主角是受劫的人：雷必須命中護體與身體，環境必須回應衝擊，成功與失敗必須具有不同的動作、聲音、空間走向及結算。

以現有 Godot 4.7.2／GDScript／Compatibility／單執行緒 Web 為基礎，採分層 2D 的景深、透視與鏡頭編排。首版先完成「一場可看懂的金丹渡劫」兩種結局，再擴大境界主題；不一次預建十二套、九界地圖或3D框架。下列時長、強度、預算是試演起點，尚未美術核定。

## 3. F5 可複用的經驗

1. **先定誰動、誰不動。** F5的盤轉、蓮花不轉、霧錯速，對應本案人物、島體、遠景及雷雲各自的運動責任。旋轉整張合成圖無法替代拆層。
2. **遮擋與完整底圖比粒子數重要。** F5-F1補完整盤，F2再改外框層序才解決遮擋。本案須檢查人物離地後原位置、佛像移開後天空、島體下沉後下緣，不能用強光遮掩缺圖。
3. **先平面運動，再投影。** 保留固定透視方向，避免已壓扁的貼圖跟著翻滾。仿3D靠景深速度、尺度、遮擋和視角切換共同成立。
4. **光暈有輪廓外衰減。** 借用F5局部mask／泛光方法，保留雷芯、人物輪廓與暗部；以同一時間開／關對照驗證，不把整屏白色當作衝擊力。
5. **隔離試演先於正式接入。** 拆層獨播、固定時刻、完整錄影和實際Web均需可查看；只有靜圖不能判定動態成立。
6. **結算與演出隔離。** 明確傳入演出時間，隱藏停算、跳過清理、低特效降級；重播無收益。字群快取與材質重用可借鑑，但不抽象成大型特效框架。
7. **證據只說實際驗過的事。** F5最新結案依簡單桌面／Web驗收；背景60／300秒FPS不是演出負載證據。本案不沿用舊數字宣稱新特效通過，也不反覆重壓F5。

## 5. 金丹渡劫第一版分鏡

建議完整首見約16–20秒，重複挑戰可選6–8秒短版，全程可跳過；低特效以靜態劫雲／關鍵姿態和約1–2秒淡入直達同一結果。時間是調參值。

| 時段 | 畫面／人物 | 空間與聲音 | 玩家理解 |
| --- | --- | --- | --- |
| 0–2秒：劫兆 | 日光褪色，吸靈突然停頓，披風逆風；保留人物輪廓 | BGM緩降，風聲逐漸變窄、遠雷進入 | 平常修行已被打斷 |
| 2–5秒：離塵 | 人物升離島面；接地陰影變淡，胸口仍是注視焦點 | 島體下移較快，遠島與淚佛較慢，前霧掠過；邊緣短時彎曲 | 人被抽離熟悉世界 |
| 5–7秒：天幕 | 下方雲海封住洞府，上方巨大弧形天幕壓入 | 一張星球弧面／星幕先建立尺度，低鳴上升後短暫留白 | 進入劫境；首版不連跳多顆星球 |

| 12–16秒：分歧 | 成功：護體重整，身體穩住，雷化細流；失敗：裂紋擴張，身影錯位，護體內縮崩解 | 成功向上開光；失敗空間向中心壓縮並轉下墜 | 結局在動作中可辨 |

雷擊不需持續高速閃白。用蓄勢停頓、近遠比例、受擊姿態、短促鏡頭位移與聲音留白建立重量。每擊間留可讀時間；背景可暗，控制與結算必須清晰。

### 失敗：修羅與餓鬼劫相

- **修羅意象**：佛像輪廓短暫變為多臂武影，裂痕如兵刃，人物影子分出相互牽扯的姿態；聲音採乾裂金屬與鼓點失拍。表現爭勝、躁動和控制失衡。
- **餓鬼意象**：遠景拉長，空洞口形和伸手剪影沿畫面邊緣向內吸氣，護體靈光像被抽走；聲音採吸氣、逆向尾音與低語紋理。表現不足、執著和無法填滿的消耗。
- 首版只選一種失敗主題完成，另一種後續變體。短暫剪影／負空間優先於整屏怪物貼圖；保留中央人物，不用大量面孔搶焦點。
- 劫相是美術隱喻，不是玩家新遭遇的可戰鬥Boss或真正投胎。結果敘事可寫「劫象侵心，護體潰散」，實際原因只說本次渡劫未成及真實規則後果，不捏造「你的心境值不足」。

### 上升與下墜的方向

成功：人物相對穩定，近島下退快、遠景下退慢；星球弧面從上方進入，雲層遮切後轉星空。失敗：先一瞬懸停，再讓周邊景物向上掠過，人物輕微下墜、空間向內收縮；最後回到原來洞府。不能同時讓人物、島、佛像以同速下移，否則只像整張海報平移。

首版採「熟悉世界→一層雲門→單一劫境→回返」。多星球穿越留高境界變體，避免最早雷劫已耗盡尺度升級空間。以上不改 `era_id`／`realm_id`／世界地址。

## 6. 舞台、素材與Godot實作邊界

預定新增小型 `TribulationStage`／演出控制器，沿 `BreakthroughSequence` 的起止訊號整合。舞台只接唯讀演出資料；用世界外觀建立臨時展示副本，原世界暫隱，結束恢復。先保留現有正式節點與輸入關係，避免把人物反覆reparent造成變換／引用失效；副本不是截一張世界畫面代替拆層。

建議層序：乾淨天空 → 星幕／星球弧面 → 遠島 → 淚佛／瀑布 → 島體及已建地標 → 島面陰影 → 人物後護體 → 人物 → 前護體／雷擊接觸 → 前霧碎屑 → 獨立清晰的控制UI。層序需依鏡頭試演核對，不照抄F5盤在框上方的特殊修正。

所有錨點採舞台安全矩形內的正規化構圖；CORE／FEET只作人物局部基準。resize重算構圖而保留演出進度；不能把1280×720固定座標直接用到Web。新圖保留共同畫布、pivot、透明安全邊與overscan，角色離島後重算雷擊終點。

素材批次：乾淨雲海底板、淚佛與瀑布mask、近／遠霧、少量遠島、單一星幕弧面；人物懸浮／受擊／失衡／回復姿態及發光mask；護體完整／裂紋／碎裂；一組劫相。島體與已接受地標優先沿用。每張保存來源、提示詞、用途、授權限制、切層、pivot、z序及雜湊。黑／灰／白底與最大位移極值都要檢查，尤其佛像抽走後補繪是否完整。原背景參考仍保留既有商用權利未獨立確認註記。

技術選擇與未知項：

- Node2D層級、AnimationPlayer／Tween和明確 `effect_time` 控制縮放、位移、透明度；鏡頭保持單一控制來源，不能同時被世界相機平滑與演出曲線牽動。
- 魚眼先對獨立背景合成紋理做短時徑向UV彎曲，中心人物另層保持形狀；長寬比校正、邊緣overscan／越界fade必驗。首版最多一個半解析度背景SubViewport；不必每層各建Viewport。
- 若選screen-reading路線，明確管理BackBufferCopy及層序，避免UI也被扭曲、多個效果讀到舊拷貝或局部拷貝之外讀出垃圾。官方機制見[screen-reading shaders](https://docs.godotengine.org/en/stable/tutorials/shaders/screen-reading_shaders.html)。本機相容性與畫質仍待試演。
- 雷電採少量可追蹤主幹／分支與多寬度柔光，護體採獨立mask裂紋／消散；人物受擊採姿態和局部光mask。首版最多同時一主雷、兩條殘留分支、96個短命碎光作初始上限，視結果減量。
- 保持Compatibility；不把compute、體積霧或Forward+專屬效果列必要條件。官方[渲染器差異](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html)只證明能力邊界，不保證本方案Web幀率。
- 音效以時間軸cue控制，預備BGM／SFX bus與保守壓低、限幅；[官方audio buses](https://docs.godotengine.org/en/stable/tutorials/audio/audio_buses.html)可供實作。Web音訊未解鎖／素材尚未載入時視覺照常，不能卡住結算；使用者靜音優先。skip、失焦、重播、場景退出均停止殘響並還原BGM，重疊演出不得重複恢復到錯音量。

## 7. 完整玩家流程與規則契約

1. **渡劫前**：唯讀預覽顯示目標境界、由規則計算的成功率、丹藥狀態及已存在的失敗後果；開始／取消清楚可達。不能顯示演出自行算的機率。金丹前的確定升境沿短演出。
2. **提交後**：正式命令只送一次，取得事件，按 `tribulation_failed`／`tribulation_passed`／普通 `era_breakthrough` 分流；命令拒絕直接回資格或容量原因，不播渡劫失敗。保存沿現有機制，保存是否成功與渡劫結局分開。
3. **演出中**：不設假QTE或讓滑鼠快慢影響既定結果。玩家可跳過、低特效；顯示狀態「渡劫演出」而非宣稱仍在即時擲骰。背景遊戲時間與離線邊界沿既有契約，不由演出新增暫停收益規則。
4. **結算**：成功列新境界／新入口；失敗列原境界→實際降至境界滿層、訓練與丹藥變化，提供「返回修煉」及已有煉丹入口。所有數值讀事件／提交前後快照，不暗示死亡、丟裝或自動輪迴。
5. **恢復**：保存失敗仍可閱讀結果，重試只保存已提交狀態。不得重新submit或重擲。重播只使用同一結果資料；本輪建議先做當次記憶體重播，重載後不假造上次失敗回放。若要永久演出歷史，另定版本化最小收據及復原，不把Node或時間軸寫入存檔。

提議演出資料包含 outcome、from_era、to_era、probability、可顯示的前後差異、visual_variant；save_status單獨更新。只採目前事件真正提供的欄位，其餘由提交前後唯讀快照組合，不在呈現層仿算規則。

### 舒適度與操作

沿共用字型、CloseSeal、44px命中和固定控制區；魚眼／色差／震動不作用在文字和按鈕。低特效停用魚眼、震動、連續粒子和移動遠景，用關鍵姿態保留受劫／失敗語意。建議完整模式也提供減少閃光與鏡頭震動選項，待實作一起接共用設定，不在單頁發明另一套控制。

短橫式優先留人物全身、主雷接點與控制；減少遠景元素和字，不縮小必要文字。切頁、skip、自然結束、重播、低特效中途切換、失焦及resize都需回復世界可見性、相機、HUD、音量和輸入鎖。
