# ADR-010：放置遊戲的 FPS 恢復驗收

日期：2026-10-04。狀態：採納；依使用者當次要求覆蓋原嚴格平均60FPS判定。

## 產品決策

常態以60FPS為目標。遊戲是放置類型，允許偶爾降至約30FPS，只要會恢復接近60；持續低FPS或隨時間／操作逐步劣化且不恢復，必須解決。60FPS不再作每組原始平均必須≥60的零容差門檻。

## 可執行判定

以下55FPS、視窗與比例是本輪將產品要求轉為可重跑工具的工程定義，並非使用者逐字指定的數值。

- 正常模式至少連續60秒，可見、ready、尺寸／DPR不變；CPU profile樣本不能作驗收。15秒仍可作快照診斷，不足以判定恢復穩定。
- 以5秒固定視窗的平均rAF cadence≥55FPS定義「接近60」。至少80%觀測時間處於這個狀態。**依2026-10-09使用者指令修訂：測試結尾的末10秒（Tail window）只要高於30FPS即可判定恢復通過**（避免因操作剛好落在測試窗口結尾而誤判為未恢復）。目標仍60，55只作主體時間允許量測抖動與少量掉幀的下限。
- 偶發30FPS後回升可通過；低谷連續10秒以上列警示，**不單憑警示阻擋**。例如60秒中間10秒30FPS、其餘60FPS且尾端恢復，契約允許通過。
- 低FPS成為常態（接近60時間不足80%）或末段低於30FPS，當次觀測不通過。未恢復可延長取樣確認；有限樣本不宣稱已證明「永久」。平坦30／逐步60→30且不回升必須不通過。
- p95／p99／max、>20ms幀與較長尖峰仍保留診斷。單個33ms、較低的樣本平均或p95>20ms，不單独自動阻擋；卡住／操作失效／保存錯誤仍按功能契約阻擋。
- 另外以正常模式5分鐘、至少50次切島／開關管理及重載前後的窗口趨勢確認沒有持續劣化；若出現不恢復的低谷，修復後重測。短60秒PASS只代表所供觀測，不能代替此長期／操作證據。

工具按每個rAF間隔與視窗的時間交集分配fractional interval count；跨視窗長間隔不得重複計數或漏掉時間。輸出保留全部樣本，無效／不同比較環境仍拒放行，不能以空白對照代替遊戲。末段判定採5秒視窗，邊界附近可保守延長觀測。

## 範圍與遷移

`desktopRecoveryGate`取代`strictDesktopGate`，值為PASS／NOT_PASSED／INSUFFICIENT_EVIDENCE。舊exact60只保留描述性統計，不決定新gate。至少一個60秒正常樣本才可PASS；短樣本或純對照僅有不足證據。既有raw與原判定保留日期，不改寫為歷史上已通過。

原手機30FPS／p95≤40ms、觸控、高DPR、啟動／下載與保存安全契約保持。手機或美術缺少證據仍待驗；此決策不直接將R2／C2標DONE，也不自動進D。當前R2收尾依恢復與持續劣化重新驗證，取消單為追求60.000而無限延伸的工作。

實作與驗證見[標準修訂驗收](../verification/res1-c2-idle-fps-policy.md)。
