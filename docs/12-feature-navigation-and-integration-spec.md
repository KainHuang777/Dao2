## 日常操作契約

- 底部四入口持續可見；選中的入口與分頁用青玉狀態標示。重新進入群組恢復該群組最近使用的分頁；重開遊戲回洞府，不增加存檔欄位。
- 同時只顯示一個玩法頁面。切頁先關閉上一頁及建築詳情；保存／Debug 工具先返回洞府，再開工具。演出仍保留自己的遮罩與相機鎖定。
- 上方固定分頁列與「返回洞府」不隨內容捲動。既有頁面關閉鈕、洞府主入口與 Escape 均能返回；較長分頁列使用 Godot 內部橫向捲動，內容使用獨立縱向捲動。
- 經營在寬橫式使用右側清單，保留左側修行與共用資源；修行／遊歷頁面使用中央工作區並暫收左側 HUD、資源及引導訊息，避免遮擋。短橫向依實際可用高度排版，不以瀏覽器捲軸解決。
- 未解鎖功能保留可查詢的分頁，動作由核心資格／費用／冷卻禁用，顯示原因。不得只因境界提高才突然新增另一份主選單。
- 輪迴資格與機緣待決在主入口及對應分頁提示。壽盡橫幅、世界地標等情境捷徑可以保留，但必須導向同一 canonical route，不能開第二份面板。

## 資源與升級的整合界線

現有解鎖庫存沿用資源清單的關閉／數量／完整三態。靈界解鎖後，把極品靈晶與天青靈液讀數加入同一資源區；已有跨世進度時追加道心／道證及正數獸魂。洞天頁只保留費用與反哺說明，避免維護另一份庫存。

目前靈晶／靈液仍是 RealmSystem 的浮點容量契約，道心／道證、獸魂是跨世進度；它們不是一般 Production 資源。共用顯示不會把它們改造成一般 Amount 庫存，也不虛構每秒速率。消耗或收益仍以各系統 Session 命令為準。

建築與洞天據點並列在「經營」分頁，保留各自解鎖、成本與 Session 命令；本輪不合併經濟規則或建築 ID。新升級項若是設施，加入經營；若是角色能力、功法或永久天賦，放在對應培育上下文。

## 後續功能接入規則

2026-10-03 RES1 規劃：保留四主入口；「經營→洞天據點」承接島總覽／島詳情／加工／航線子視圖，建築頁可依島篩選；煉丹入口與材料加工使用共用配方／權威庫存核心。世界點島、點工坊与清單導向同一工作記錄，沒有第二份遊戲狀態。庫存總覽須區分可用、在途、保留與分島明細；現行靈界 float／丹藥雙表示在接新配方前要完成顯式遷移。這是 RES1-A–C 待實作契約，下表現況不代表已存在多島物流。見 [docs/14](14-multi-island-resource-progression.md)。

1. 先選唯一主歸屬及穩定 route，登記在 `feature_navigation.gd` 的 GROUPS；新系統不得直接往 More popup 或底部另塞按鈕。
2. 資源只追加共用清單；操作放在功能頁。需要情境捷徑時呼叫同一 `open(route)`。
3. 頁面提供 `set_layout_bounds(Rect2)`，使用 Theme、至少 44 邏輯像素命中區、容器與內部捲動。不得假設自己擁有整個 viewport。
4. UI 讀 Session view，送命令，再依結果保存／刷新；不得直接改 GameState、庫存或發放收益。只切分頁不能改遊戲規則。
5. 新增功能必須補群組歸屬、單頁互斥、返回與短橫向驗證；正式命令另有成功／拒絕／保存證據。完整手機觸控與 IndexedDB 驗收保持獨立。

實作索引：`feature_navigation.gd` 統一入口與頁面生命週期；`system_actions_panel.gd` 呈現靈獸／界域決策。驗證與未完成項見 [NAV1 驗收](verification/feature-navigation.md)。
