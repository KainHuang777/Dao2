## 3. 里程碑與完成條件

### M0：固定來源與技術探針

輸入：舊碼路徑、目前規劃、可用電腦／手機。成果：可重現的工具鏈、跨語言測試向量規格與一個 Web 探針。

1. 記錄舊版提交、未提交變更清單、package 版本、`src/data` 與設定來源 hash；區分 development／release profile。不得改動原碼來消除基線差異。
2. 把公式 parity 中的記錄值整理成 JSON fixture 規格，註明輸入、預期結果、誤差政策與來源行號；先做建築費用、容量、修煉時間、道心道證與輪迴。
3. 固定 Godot 與模板；驗證 CLI import／專案測試 runner／Web 匯出。
4. 大數探針對齊舊版解析、算術、比較與序列化；RNG 探針對齊固定測試向量。
5. Web 探針驗證繁體中文字體、點擊、音訊啟用、resize、存檔持久化、重新載入及基本 Shader。

完成條件：上述結果可由同一套命令重跑，有實际瀏覽器結果；對數值或儲存仍不確定的部分有明確失敗案例和處置。M0 不以一張漂亮畫面宣告通過。

### M1：規則、時間與存檔骨架

建立 GameState、Amount、Command、TimeAdvancer、SaveCodec 與 LegacyImporter 的最小實作。移植新手解鎖、費用、容量、產率、等級、壽元和一組輪迴結算案例。舊碼已有純規則先沿用語意，不從 UI 反推。

完成條件：代表性黃金 fixture 通過；分段時間推進一致；非法指令不改狀態；存讀檔 round-trip；倒退時鐘／壽盡邊界／崩潰重試不重領；未知大數或未知資源 ID 有明確匯入結果。此階段可以只有開發面板。

### M2：人界洞府完整視覺切片

採一座洞府，使用原作必要新手鏈：茅屋、木屋、林場、採石場、靈植場與所需倉儲。只做通往第一個升境目標所需的功法、材料與配方；具體清單由原資料依賴圖決定，避免漏掉先決條件或另造假門檻。

成果包括場景點選、資源流向、缺料／容量滿狀態、升級变化、修煉動態、第一次升境演出、離線摘要、存讀檔。另用明確標示的高階測試存檔展示渡劫，不把雷劫硬塞入原本無渡劫的新手階段。

完成條件：新手能辨認目標與瓶頸，場景／規則一致；首次升境可完成；低特效不改收益；桌面與指定手機 Web 通過核心操作。正式節奏以舊版基線比較，測試加速需明確標示。

### M3：輪迴與舊系統移植

先完成輪迴資格、獎勵預覽、實際結算、保留／清除清單與新一世。驗證道心保留和購買天賦的取捨，沿用原先已有的自動化解鎖語意。之後逐項接入丹藥、天時、宗門、機緣、靈獸、成就與多語內容。

完成條件：一次輪迴前後與 fixture 對照；重讀不多給獎勵；新一世可正常成長；每個已宣稱移植的系統都有代表性驗收。Era9–12 需補高階測試，不能依靠舊模擬器目前的 Era8 上限推定通過。

M3 先完成代表性多世循環即可進行 M4 的小型探索，但完整舊玩法承接狀態必須由功能矩陣逐項記錄，不可提前宣稱全部完成。

### M4：第二界與尺度切換

人界之外加入一個手工第二界，建議以靈界的週期供給為第一個提案。完成洞府 → 區域／世界 → 星域的鏡頭過渡、九界總覽索引和最多三個活躍據點。

完成條件：兩界有可說明的策略差異；切圖不改收益；玩家可返回原洞府；資料新增能描述大部分第二界內容。若每一界都需大量改寫核心，先整理具體共通規則，不急做完整九界。

### M5：受控宇宙與逐界內容

三種以上手工規則原型驗證後，才加入生成器、候選世界、探索決策和封存機制。逐界製作內容與美術，不一次承諾九套全新系統。

完成條件：相同地址／版本可重現；既有世界更新後不洗掉；抽樣生成無不可達必需資源、無非法法則組合、無可重複無限套利；存檔和活躍據點負載受控。生成抽樣通過不能代替人類對重複感與策略差異的試玩。

## 4. 驗收案例清單

| ID | 輸入／操作 | 必須看見的結果 |
| --- | --- | --- |
| RULE-01 | 新手 schema1 空白狀態 | 只有靈力與茅屋的初始入口；無隱形免費產率 |
| RULE-02 | 茅屋到2、木屋到2、林場到3 | 依舊規則依序解鎖；容量按 schema 語意保留 |
| RULE-03 | 庫存充足但容量不達升境門檻 | 回傳容量不足；不可把庫存直接當容量 |
| RULE-04 | 同境連續提升小等級 | 修煉時間按累積規則；未歸零成新一輪等待 |
| RULE-05 | 無天賦丹藥的練氣／築基／金丹 | 壽元上限80／200／740；升境不清本世年齡 |
| RULE-06 | 輪迴前B=100、當境築基 | 基線道心15；普通道證2／大道道證3，其他傳承依清單 |
| RULE-07 | 購天賦／輪迴／靈獸轉世 | 核心資格與資源檢查；保留、消耗、獸魂與清空一致 |
| TIME-01 | 同seed、同命令時間點，600秒一次／分段 | 同等最終狀態、RNG與事件；依Amount政策比較 |
| TIME-02 | 離線跨缺料、容量滿、丹藥到期、壽盡 | 在邊界改變產率或停機，摘要可解釋 |
| TIME-03 | 離線48小時並連續重載 | 收益最多最前24小時且受壽元限制，年歲／期限推進48小時，剩餘時間不因重載再領 |
| SAVE-01 | 結算後關閉報告、重載、重試 | 同一區間不重複入帳 |
| SAVE-02 | 寫入中斷、檔案損壞、儲存不足 | 取得上一完整世代或明確失敗，不覆蓋所有有效資料 |
| SAVE-03 | 同一存檔兩分頁、舊分享碼缺獸資料 | 單一寫入者；缺失列報告，保留原文 |
| AMOUNT-01 | 巨量成本、近容量、第二層指數字串 | 不溢位成Infinity、不静默歸零；不支援值明確拒絕 |
| RNG-01 | 舊SeededRandom測試向量 | 序列一致；特效增減不消耗玩法RNG |
| VIEW-01 | 关闭所有粒子，30／60FPS切換 | 經濟結果一致，状态仍可读 |
| VIEW-02 | 真實手機點建築、開抽屜、升境與返回 | 操作不被遮擋，結果與畫面一致 |
| WORLD-01 | 同地址生成、換視角、存讀檔 | 世界身份一致，進度不複製或遺失 |

表中數值基線已由讀碼取得，但以上測試均尚未在 Godot 執行。舊行為若確定是缺陷，寫入規則差異清單並定義 v2 預期，不為了通過同等性測試而保留壞存檔或重複領獎。

## 5. 暫定效能與視覺品質預算

先選定一台桌面與一台中階手機，記錄型號、OS、瀏覽器、解析度和品質檔。下列是設計起點，需在 M0／M2 量測後校準，並非已達成的效能。

| 項目 | 暫定門檻 | 測試條件 |
| --- | --- | --- |
| 桌面 | 60 FPS目標，p95 frame time ≤20ms | 三分鐘洞府操作，包含一次升境演出 |
| 手機 | 30 FPS目標，p95 frame time ≤40ms | 同一流程、相同狀態，採適合該裝置品質檔 |
| 可互動冷啟動 | ≤10秒；必要壓縮下載量先以30MB為上限 | 冷快取、20Mbps／100ms延遲；分別記下載、引擎啟動與首互動時間 |
| 操作回饋 | 按壓／接受回饋≤100ms | 不含規則要求的等待；長結算有進度與可恢復狀態 |
| 文字與觸控 | 360 CSS px寬無關鍵裁切；主操作約44×44 CSS px以上 | 實測CSS尺寸，開大字模式與底部抽屜 |
| 離線推進 | 24h壓力案例避免單一長阻塞；超過200ms顯示進度 | 同時計算缺料、容量、自動化、壽元邊界 |
| 長時間運作 | 切換場景50次後記憶體無持續線性成長 | 分別觀察資產、粒子池、事件訂閱與存檔大小 |

必要下載量如果因基礎 WASM 已逼近預算，先量測基礎包、裁剪未使用內容、延遲非必要資產，再修訂预算。不能以「Godot 可以匯出」代替載入體驗驗收。

視覺验收另看：建築前後差異、主光源一致、透明邊緣無雜色、文字可讀、鏡頭有尺度感、頻繁回饋不蓋過突破、減少動態模式完整。概念圖與引擎成品分開標記。

## 6. 範圍與工作量管理

主要不確定性按優先級為大數相容、原作／模擬器差異、Web持久化、單場景美術返工、手機透明特效負載。M0完成後才按實際速度拆人日；AI能加速產出，但不能把試玩與實機驗證省略。

首切片延期時先縮減裝飾、非必要配方、演出變體和次要導航，不砍掉保存、規則契約或唯一代表性突破。宗門多人化、雲端帳號、市場交易、即時戰鬥、完整九界、全3D自由漫遊與執行時AI劇情不在首切片範圍。

## 7. 歷史初始任務（已由根目錄 Roadmap 接替）

建議從以下任務開始，而不是直接要求生成整個九界遊戲：

> 閱讀本工作區 README 與 docs/00–03 規劃文件，開始修仙問道 v2 的 M0。舊版來源 E:\Python\test1 僅供唯讀對照，先遵守其 AGENTS.md 與 user_rules.md；新產物寫入 E:\WORK\Dao2。記錄舊版資料與規則來源，建立跨語言 fixture 規格，核對 Godot 4.7.2 與同版 Web 模板，完成可重現的最小 Web／字體／輸入／存檔探針和 Amount／RNG 相容性探針。不要開始完整九界內容。每項完成需附執行指令、實際結果及剩餘限制；若大數或Web持久化不達標，先記錄決策與替代路徑，替代路徑通過相同驗收後才繼續依賴工作；其間可進行不依賴該能力的工作。

後續每個任務只處理一條可驗收能力，交付檔案範圍、fixture、驗證命令和實际結果。調整產品需求時同步更新規則差異與里程碑；不要在本规划之外悄悄把原作變成另一套經濟。
