# 修仙問道 v2：遊戲介面沉浸感與視覺品質升級建議書（Game UI Immersion & Aesthetic Proposal）

本文件記錄「擺脫網頁拼湊感、提升 Godot 遊戲引擎原生沉浸質感」之架構建議與落地方案，留存供未來 UI/UX 與視覺里程碑排程執行。

---

## 一、 背景與核心痛點

### 1.1 現象：AI 輔助開發下的「網頁感」問題
當前透過 AI 代理產生的 Godot 介面雖然功能邏輯完整、排版工整，但在視覺風格上容易呈現出類似「現代 Web 後台管理系統」或「Tailwind/Bootstrap 卡片流」的拼湊感，缺乏一款遊戲應有的氛圍沉浸感（Immersion）與打磨度（Game Polish）。

### 1.2 第一原理剖析（Root Cause Analysis）
* **語料偏差**：大型語言模型（LLM）的訓練資料中，Web UI（HTML/CSS）佔比極高，預設直覺傾向使用純色扁平容器（`PanelContainer` + `StyleBoxFlat`）、標準網格與垂直流（`VBoxContainer`/`HBoxContainer`）及單純背景變色的按鈕。
* **通用平面/網頁設計 vs 遊戲介面設計**：
  * **通用/網頁設計**追求：資訊閱讀效率、留白、扁平化、幾何極簡。這能保證介面「乾淨」，但會抹殺「遊戲世界觀」。
  * **遊戲介面（Game UI/HUD）**追求：**世界觀融入（Diegesis）、材質感（Tactile Texture）、微動態反饋（Game Feel/Juiciness）與畫面張力**。

## 二、 核心升級方向（四大支柱）

```
                     ┌────────────────────────────────────────┐
                     │   遊戲引擎級沉浸 UI (Game Immersion)   │
                     └──────────────────┬─────────────────────┘
                                        │
     ┌──────────────────┬───────────────┴───────────────┬──────────────────┐
     ▼                  ▼                               ▼                  ▼
【材質與主題】     【微動態反饋】                  【著色器特效】     【空間與佈局】
Theming & Texture   Juiciness & Tween               Godot Shaders      HUD & Composition
- 九宮格切片紋理     - 按鈕 Hover 彈跳彈性縮放      - 靈氣/金光掃過    - 四角 HUD 定位
- 玉簡/竹簡/金邊     - 點擊按壓下沉與粒子回饋       - 水墨消融/扭曲    - 卷軸展開/浮層抽屜
- 禁純色 Flat 樣式   - 視窗彈入展開/淡出緩動        - 呼吸發光 (Glow)  - 非對稱有機排版
```

### 支柱 1：材質與主題體系（Theming & Textures）
* **淘汰純色 `StyleBoxFlat`**：常態遊戲主視窗、功能彈窗、主要按鈕一律禁止使用灰黑純色色塊，改用 **`StyleBoxTexture`（九宮格 / 9-Patch Slice）**。
* **專屬材質庫建立**：
  * **修仙底框**：玉簡、古籍羊皮紙、竹簡、玄鐵牌匾。
  * **裝飾邊框**：祥雲紋、回字紋、八卦雕角、金絲包角。
  * **按鈕紋理**：硃砂印章、靈石按鍵、懸浮金匾。

### 支柱 2：微動態反饋（Juiciness & Game Feel）
* **動態響應（Tweening）**：
  * 所有可互動控制項（按鈕、卡片、圖示）在 Hover 時具備彈性縮放（`scale: 1.0 -> 1.05`，配合 `TRANS_BACK` 緩動）。
  * 點擊時有明確的按壓下沉感（`scale: 0.95`）與音效觸發。
* **彈窗與視窗轉場**：
  * 嚴禁瞬切 `visible = true`。
  * 視窗開啟具備「自中心微縮放彈出 + Alpha 淡入」或「竹簡/卷軸自兩側展開」的補間動畫（200ms~300ms）。
* **操作反饋**：收穫、突破、升級時伴隨飄字（Floating Combat Text）、粒子微爆（CPUParticles2D）。

### 支柱 3：Godot 著色器特效（Shaders）
* **流光與靈氣（Sweep / Glow）**：高階卡片、主要操作按鈕加入週期性的金光或靈氣流動 Shader，打破純靜態畫面的呆板感。
* **邊緣與遮罩（Dissolve / Mask）**：面板展開或切換分頁時，採用水墨擴散（Ink Dissolve）著色器遮罩。
* **背景擾動（Screen Reading / Heat Haze）**：洞府主畫面與重要全螢幕彈窗後方加入帶有微微模糊或水墨擾動的動態背景。

### 支柱 4：空間與空間佈局（HUD & Composition）
* **打破「中央垂直捲軸大方塊」**：
  * 採用經典遊戲 HUD 配置：四角定位裝飾錨點、環形或扇形輪盤選單、不規則形狀的靈氣/境界儀表。
  * 側邊抽屜式展開（Drawer Navigation）搭配傳統卷軸飾條。

## 四、 執行排程定位與相依性

* **排程時機**：
  * 本建議書定位為**後續視覺打磨里程碑之工作指針**。
  * 不打亂當前功能邏輯推進（如 P2 系列、核心玩法循環驗收）。
  * 建議在核心系統玩法閉環後、或大型 UI/UX 換代（例如 M1/M2 里程碑之 UI 整合階段）時集中開立任務推動。
* **相容性約束**：
  * 必須嚴格遵守 `docs/07-responsive-ui-web-spec.md`（三橫式桌面響應式、錨點不脫框、44px 觸控友善範圍）。
  * 著色器與粒子必須確保在 WebGL / Compatibility 單執行緒環境下維持 60 FPS 效能標準。
