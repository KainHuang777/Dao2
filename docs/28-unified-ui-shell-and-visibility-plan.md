# 全介面顯示規則與版型重構規劃

2026-10-21 · `UI-SHELL-PLAN`。**規劃與靜態盤點DONE；樣張／實作／介面驗收TODO。**

使用者要求把HUD、資源、中央訊息、開關與恢復規則，一起納入本次研究衍生的介面重構。本文件擴大[一世卷末整合規劃](27-life-report-and-decision-ux-integration-plan.md)的共用外框範圍，優先處理顯示一致性，再接小傳、抉擇與帳目。下文是具體推薦設計，並非所有版型已接受或已實作。

## 1. 決策摘要

1. **一般玩法頁保留精簡HUD**，洞府保留完整HUD。狀態可以常駐，完整左側面板不必常駐；演出、阻擋型報告、儲存保護及旋轉提示有明確例外。
2. **有付出／消耗的頁面自動提供相關資源**。寬式可並列資源欄，短橫式改頁內情境資源列；每個付款操作旁仍有持有／需求。閱讀型頁不自動展開全部庫存。
3. **中央長訊息預設只在洞府按偏好顯示**。功能頁使用頁內結果；全域重要狀態有固定提示位置。不能因關閉中央訊息就看不到保存失敗或壽盡。
4. **開關只表達玩家意圖，顯示由共用規則計算**。自動展開不改洞府偏好；視窗變小不改玩家開關；關閉／重開不靠逐層布林值拼回畫面。
5. **先定共用外框，再做各頁樣張與搬遷**。沿現有Godot、四主入口、GameTab、SegmentChips、CloseSeal與已接受美術，先不增加新主選單或另造每頁皮膚。

## 2. 現況盤點：不一致的來源

靜態來源與SHA256見[盤點](verification/artifacts/ui-shell-plan/source-audit.json)，本輪未將靜態判斷宣稱為瀏覽器已重現。

| 位置 | 實際可見行為 | 重構要消除的耦合 |
| --- | --- | --- |
| `feature_navigation.gd:PAGE_POLICY` | shared／wide_stock／hud_stock／inline等資源規則；煉丹不同於其他中央頁 | 頁面名稱決定例外，缺少「玩家任務需要什麼」的共用語義 |
| `FeatureNavigation.open/home` | 從洞府進頁時存resource mode，經營／煉丹可自動改mode，home再恢復 | 偏好與臨時顯示混同；跨頁與工具流程難追蹤 |
| `FeatureNavigation.layout` | 中央頁再覆寫header／resource_ribbon，建築以外隱藏hint | 與HUD controller共寫同一批visible；結果依呼叫順序 |
| `AbodeHudController._layout_overlay_panels` | 先顯HUD／資源，短建築頁再收起；晉階／突破reparent至建築頁 | 主動作隨頁搬移，狀態與動作位置不固定 |
| `AbodeHudController`訊息控制 | messages_open與messages_explicit、hint_panel.visible共同影響開關；建築寬度也讀訊息狀態 | 「想開」與「目前能顯示」混用，訊息又改變頁面寬度 |
| `abode_modal_manager.gd` | 管理工具／報告／演出與多個歷史開關入口 | 需確認正式入口均走canonical route；不能只改一條呼叫路徑 |
| 壽盡／離線／保存保護 | 有既有提醒、延遲與重試流程 | 不得被新HUD收合或訊息偏好蓋掉 |

例外曾解決個別頁面問題，不能以「不一致」否定過去驗收。重構保留既有收益、缺料、保存拒寫／恢復與開放門檻；改的是共用佈局責任與資訊位置。

## 3. 三層資訊與顯示優先序

| 層 | 內容 | 常態規則 |
| --- | --- | --- |
| 全域狀態 | 境界／層級、修煉進度或就緒、壽元、重要待辦、保存狀態 | 一般玩法頁精簡常駐；洞府可展開完整HUD |
| 任務上下文 | 當頁材料、專用貨幣、容量、操作結果、當前島／界域 | 頁面需要就顯示；跟隨當前資料，不依洞府資源開關 |
| 閱讀與歷史 | 中央訊息全文、過往操作、小傳與帳目 | 玩家按需閱讀；一般頁不自動插入中央長面板 |

顯示與輸入優先序：儲存／復原保護與旋轉阻擋等必要安全層 → 已啟動演出／正式結果報告 → 當前確認或工具層 → 當前功能頁 → 共用HUD／導航 → 世界。這是邏輯優先序，不是每類固定Canvas index；例如演出中保存失敗仍須透過保護層可見可重試。旋轉提示不可使必要復原資訊永久不可達，轉回橫式恢復。

一般提示不能搶走已有確認、離線報告或演出的焦點。壽盡在安全時機沿既有路由提醒一次；其餘待辦只更新圖示／短訊息，不開第二頁。背景仍可繼續模擬，是否阻擋核心命令沿原規則，不以UI隱藏當暫停。

## 4. HUD是否永遠存在？

**推薦：玩法中的修行狀態常駐，完整HUD只在洞府展開。**

精簡HUD固定為同一位置與同一組欄位：境界／層級、修煉進度或「可晉階」、壽元已用／上限。時辰／天候在可用空間顯示，短式可進詳情；重要BUFF與宗門完成／機緣待決等沿現有共用通知入口，不每頁再造一條。

晉階／突破只設一個共用動作位置，正式頁不得自行reparent。短式先保資訊與44px動作，詳細門檻可展開；若操作需要離開會失效的確認，先取消該確認再沿原命令流程，不讓兩種提交並行。

| 畫面模式 | HUD | 四主入口／設定 | 輸入 |
| --- | --- | --- | --- |
| 洞府 | 完整修行HUD | 顯示 | 世界可操作，UI區阻擋穿透 |
| 任何一般玩法頁 | 精簡狀態列 | 顯示 | 功能頁可操作；建築／空島是否保留世界選取按版型，不因管理群組一概放行 |
| 功能頁內詳情／確認 | 原精簡HUD可見 | 可見但由確認規則限制操作 | 頁內單一提交；離開／切頁即取消未提交確認 |
| 設定／保存／Debug工具 | 精簡狀態作背景或可讀摘要 | 模態期間停用後方操作 | 關閉回原合法route，不為開工具先跳洞府 |
| 離線摘要／規則通知 | 報告優先；可保留不互動摘要 | 後方停用 | 完成必要報告後回原route；首啟動仍回洞府 |
| 一世卷末一般閱讀 | 精簡；若壽盡明示已壽盡 | 顯示 | 小傳、帳目與抉擇按需切，不自動轉世 |
| 輪迴／突破演出 | 隱藏普通HUD | 隱藏或停用；保留skip與必要保護 | 演出層唯一輸入，不攔保存重試 |
| 儲存保護／復原阻擋 | 必要狀態與結果由保護頁承載 | 一般動作停用 | 不用Esc繞過需要完成的保存處置 |
| 直式 | 旋轉提示取代正式玩法 | 不提供玩法操作 | 轉橫後重新計算布局，保留合法route |

此表取代的是未來實作方向，不宣稱目前每頁已有精簡HUD。完整HUD的裝飾、通知與字級在UI-SHELL-DESIGN做三橫式樣張，不先固定新尺寸。

分為「庫存工作」、「專項消耗」、「閱讀」三類。自動開啟的是**相關資料視圖**，不代表把洞府「關閉」按鈕強制永久改成「數量」。

| route／子頁 | 類別 | 預設帶出的資源／貨幣 | 不可省略的就地資訊 |
| --- | --- | --- | --- |
| buildings | 庫存工作 | 目前建設材料與一般庫存；可查全部 | 每張卡原有材料圖示、持有／需求 |
| outposts | 庫存工作 | 所選島的當地可用／保留／在途與容量；靈界據點時改靈晶／靈液 | 開拓／升級成本、實際資料範圍，不混全島與當地庫存 |
| manufacturing | 庫存工作 | 當前島／篩選的原料與成品、容量 | 配方材料、批數／保留量與工作狀態 |
| transport | 庫存工作 | 選定來源／目的地、在途／預留與容量；未選航線用列表摘要 | 航線設定、運量／需求、草稿與已生效設定分開 |
| alchemy | 庫存工作 | 煉製材料、相關丹藥庫存 | 每方可用／需求與每丹持有量；不再特殊保留完整左HUD |
| skills | 專項消耗 | 技能點；有其他成本再納入相關資源 | 當前點數與研習費用／資格 |
| beasts | 專項消耗 | 餵養材料與當前獸種獸魂 | 餵食需求／冷卻、獸魂天賦成本 |
| sect | 隨子頁 | 山門／歷練先貢獻摘要；功法／坊市帶貢獻與相關材料 | 派遣要求、領取狀態、實付費用；不因切宗門分頁改洞府偏好 |
| fortune | 專項消耗 | 待決選項涉及的成本資源；無成本事件不開空欄 | 精確持有／需求；選後實得收據 |
| decisions | 專項消耗 | 當前界域法令的貨幣／材料 | 資格、費用、冷卻；realm與era分清 |
| reincarnation：轉世／生平 | 閱讀／預覽 | 不展開全部庫存；道心道證持有／當次所得各一份 | 保留與重置、當次正式預覽 |

## 6. 中央訊息何時顯示？

先把現有「訊息」拆成職責，避免一個hint panel同時裝目標、錯誤、操作說明與世界敘事。

| 類別 | 顯示位置／時間 | 收起／優先規則 |
| --- | --- | --- |
| 下一步目標 | 洞府固定一句目標，點開說明；功能頁只保留可用的目標入口 | 不每tick彈中央長文；完成後更新文字 |
| 中央歷程／世界文字 | 洞府中央閱讀區，沿玩家開／關偏好 | 一般功能頁自動暫收；回洞府依偏好恢復，不被事件硬開 |
| 玩家主動閱讀訊息 | 共用閱讀層，顯示歷程／說明 | 可從任意頁開；暫蓋／取代閱讀內容，後方操作停用；關閉回原頁，不壓縮原卡片寬度 |
| 當頁操作成功／拒絕 | 原頁固定回饋區；成功可短暫摘要，收據可再查 | 不只寫入中央長訊息；切頁不把舊成功訊息套新頁 |
| 保存失敗／復原 | 固定全域狀態區＋當頁詳細錯誤與重試；必要時保護層 | 不受訊息開關影響，不自動消失；重試只保存 |
| 機緣待決／宗門完成／成就可領 | 既有共用通知／route標記 | 以狀態更新，不反覆彈頁；點入canonical route |
| 壽盡 | 全域精簡狀態明示，安全時沿既有輪迴提醒一次 | 等報告／演出；關閉後不重搶頁；既有新世／重載政策保留 |
| 突破／輪迴結果 | 正式結果層／演出結算卡及回執 | 事件決定結果；一般toast不遮蓋 |

重要通知不只靠顏色、聲音或短暫toast。訊息歷程是閱讀工具；「已保存的小傳／抉擇簿」是版本化正式紀錄，不能把記憶體HUD文字當持久化帳簿。本階段只規劃位置與路由，不宣稱新增永久通知中心。

## 7. 統一版型

三種共用殼：洞府世界、功能工作區、閱讀／保護覆層。依docs07斷點與實際最小可用空間集中選擇；高度不足也應切短式，不讓每頁另猜斷點。

### 寬式功能頁

```text
┌ 共用精簡HUD：境界／修煉／壽元／重要狀態        設定 ┐
├ 群組分頁／當前頁題／固定關閉                         ┤
│ 情境庫存欄（需要才有） │ 當前功能內容／頁內子分頁      │
│ 獨立內捲               │ 內容獨立內捲                 │
│                        │ 成本與操作留在原卡／原列      │
├ 全域異常提示或當頁回饋（有狀態才留空間）              ┤
└ 四主入口：洞府／經營／修行／遊歷                      ┘
```

建築／空島寬式仍可使用右側清單與可操作世界；此為同一殼的world_rail配置，不代表另一套HUD與訊息規則。當完整清單／資源／世界安全區無法共存時，切工作區模式；不硬留一小條不可操作世界。

### 短橫式功能頁

```text
┌ 共用精簡HUD（同位置／同語義）                 設定 ┐
├ 群組分頁／返回                                      ┤
├ 情境資源短列（需要才有）＋ 展開資源                  ┤
│ 當前頁的單一閱讀／操作區；長內容只在此內捲           │
├ 當頁回饋／保存異常／必要固定動作                     ┤
└ 四主入口                                           ┘
```

這是語義分區，不要求每列都常駐或固定同高。短式可把頁題併入分頁、資源摘要併入頁首；但不得刪掉進度／壽元、成本／資格、關閉、保存重試或縮小44px動作。若上下分區已過多，先減裝飾／重複標題、把詳情移內捲，再討論壓縮，不能以裁切驗收。

## 8. 開啟、關閉、切頁與恢復契約

**偏好與有效顯示分開保存於呈現層。** 概念上分為：

- `home_preferences`：洞府庫存關閉／數量／完整、中央訊息開關等玩家選擇；既有保存行為不因本次規劃擴大。
- `route_context`：當前route／子頁／島嶼、草稿與捲動；暫存期間沿原頁契約保留，不保存Node參照至GameState。
- `user_override`：本頁是否暫收資源或主動開閱讀層；不得從Control.visible反推意圖。
- `overlay_state`：頂層工具／閱讀／確認／演出／保護狀態，以及返回目標。
- `effective_layout`：上述狀態＋viewport＋資料可用性導出的顯示、bounds與輸入權限；不寫回偏好。

| 行為 | 統一結果 |
| --- | --- |
| 洞府→功能頁 | 套route政策與精簡HUD，不改洞府偏好 |
| 功能頁A→B | 原頁未提交確認取消；保留應保留的草稿／捲動；直接按B政策計算，不先短暫回洞府 |
| CloseSeal／洞府主入口 | 回洞府，依目前viewport＋洞府偏好重新計算；不用恢復一堆舊visible |
| 詳情內返回 | 回本頁列表；全頁關閉與「返回列表」語義分開 |
| 工具／訊息層開關 | 記一個合法返回route；關閉回原頁，若該route已隱藏／失效則回群組可用頁或洞府 |
| Escape | 處理最上層可取消對象：工具／閱讀→頁內確認→詳情→功能頁；不可關掉必要保護或直接跳過保存 |
| 視窗大小變更 | 重新算effective_layout，不改偏好；原資源抽屜意圖可維持，寬式轉欄／短式轉抽屜的實際呈現另定樣張 |
| 直式→橫式 | 恢復合法route與草稿／捲動，未提交確認按原取消契約處理；不自動發命令 |
| 壽盡／輪迴後開放條件變化 | 對新View重驗route；清除不合法提交狀態，不能復活舊頁或舊天賦價格 |
| 關閉但核心仍pending的機緣 | 暫收不等於取消；重開同一pending，成本刷新、不重抽 |
| 重載 | 依既有規則回洞府；存檔中的pending／結果與呈現記憶分開，不新增UI存檔欄位冒充恢復 |

工具層同時最多一個；深層說明可在同一工具內替換，不導入任意多層彈窗堆疊。保存保護等高優先狀態可打斷，但舊層的結束回呼須檢查目前狀態，不能用過期camera/input快照解鎖新層。

## 9. 實作責任分工（候選架構）

先在既有FeatureNavigation與HUD controller之間整理政策解析；是否抽一個小型 `UiShellPolicy` 由UI-SHELL-0決定。不要先建通用路由框架。

輸入：route、子頁／資料上下文、viewport類型、使用者呈現意圖、overlay、重要狀態。輸出：HUD模式、資源模式／範圍、訊息模式、導航模式、世界輸入、工作區bounds。政策解析為純呈現，不重算費用、不改存檔／庫存。

頁面宣告需求，例如 `resource_context=inventory/focused/none`、`workspace=world_rail/workspace/reading`；列出所需資源來源，由Session View供值。資源顯示有單一管理者；頁面只管理內容內的成本與操作。共同元件visible最後只由殼套用一次，單頁不得再直接hide/show全域header／resource_ribbon／hint_panel。

彈層與相機／輸入也由同一呈現狀態協調；`abode_modal_manager`既有工具與歷史fallback入口需逐一核對，未證明不可達前不刪。保存、離線與演出回呼必須以現在的route／overlay重算，避免舊回呼把別頁打開。

## 11. 必驗狀態矩陣

後續實作須覆蓋以下序列，不能只拍每頁獨立截圖：

1. 洞府庫存關閉／數量／完整，各自進建築→煉丹→技能→回洞府；自動資源顯示正確、洞府偏好不變。
2. 洞府中央訊息開／關，各自進製造→主動讀訊息→關閉→回洞府；工作區不被訊息擠寬、偏好不被篡改。
3. 寬式開資源欄→短式→主動資源抽屜→關閉→寬式；當頁草稿／捲動、成本與44px動作保持。
4. 同一pending機緣暫收→建設花費→回機緣；同事件、負擔能力更新、不得用舊數值提交。
5. 任意頁開設定／保存工具再關閉；回原合法頁，背景不穿透、不亂解鎖世界相機。
6. 保存拒寫→切頁／開工具→重試成功；錯誤不因中央訊息關閉而失蹤，不重送原命令。
7. 壽盡發生於功能頁／離線報告／演出期間；提醒等候且僅一次，關閉後可手動重開；提前轉世不顯示已壽盡。
8. 開未提交轉世／突破／法令確認後切頁或按Esc；只取消確認，不自動付款、不關閉保護層。
9. 九界預覽、建築世界捷徑與四主入口均到同一route；無第二份面板、工具／演出返回不恢復過期頁。
10. 直式旋轉提示→橫式；僅驗桌面resize與提示流程，不聲稱實機／觸控已通過。

CLI驗證policy與狀態轉移；原生驗布局／生命週期；真實桌面瀏覽器驗滑鼠、捲動、重開、拒寫／重試與重載。受影響回歸通過後再按必要範圍全量檢查，不重跑與改動無關的已接受長時效能矩陣。
