# ECON-R1-D1：Era4 批量凝石與分階深採

本節是 D 的第一個可驗收子階段，完整 D 尚包括後段構件、R12–R14、Era5–6、五宗／散修／多世對照；完成判定與命令結果只記於 [開發狀態](../development-status.md#econ-r1-d)。

## 入口與保存

`EconomySlice.create()` 保留 C 的七研究／Era3 邊界；`create_late()` 另組 R01–R11，內容尾標 `+econ-r1-c-1+econ-r1-d1-1`。仍由 `EconomyProfile.open` 明確啟用，正式 launcher 不切換。D1 外層 rules/economy 為 `econ-r1-rules-3`／`econ-r1-economy-3`；schema／研究資料形狀仍為1，catalog SHA 另驗全部11節點。

不自動把 C/B/現版存檔升降版。authenticated 不相容 main 或 backup 會拒載，來源保持原文，不能靠 fallback 蓋過新版本。寫入拒絕維持原 live state、凍結候選與暫停命令，恢復後重試相同 bytes；既有來源歸檔與兩槽 readback 沿 B。

## 工藝階梯

| 研究 | Era／前置 | 祖島試製費 | 無傳承秒數 | 權威能力 |
| --- | --- | --- | ---: | --- |
| R08 批量凝石 | 3／R07；中石 `ever_obtained` | 中石20＋陣芯2 | 1800 | Era4 既有 `stone_mid_bulk` 配方，100中石／批；不是研究時直接發貨 |
| R09 深採I | 4／R05；寒銀島已開 | 陣芯3＋銅精10 | 2400 | 精鐵採集；寒銀調度建造資格 |
| R10 深採II | 4／R09；寒銀島已開 | 精鐵10＋陣芯2 | 3600 | 寒鐵採集；元嬰聚靈庫資格 |
| R11 深採III | 4／R10；寒銀島已開 | 寒鐵10＋符咒10 | 5400 | 秘銀採集；後段陣匣配方留 D2 |

元嬰修行陣另需 R08。研究不送設備，不改原有設備成本／產率；三種礦物的原始速率仍為0.1／0.05／0.05，寒銀調度仍使其加倍。採集階數不是採集器等級，也不是物品的加工深度。

寒銀開島只支付既有木100＋中石20＋陣芯2，不要求自己的未解鎖金屬，開島後三種金屬的產率均為零。R09 用前階材料，R10 用先取得的精鐵，R11 用先取得的寒鐵；沒有首件自我依賴。`ResearchSystem.quote/start` 檢查前置、島嶼、設備、實物樣品與材料，失敗不扣款。

`IslandEconomy.rate(state,island,resource,catalog)` 在新版上下文檢查每個金屬的研究；普通逐秒、prepared 分支及 manufacturing view 使用同一邏輯。buff 的預先取樣 local rate 也不能繞過未研究的零產率。研究在該秒生產／運輸／加工之後完工，下一個權威秒才開始新採集；完工時清除命令區間快取，防止閒置快取保留舊資格。

R08 材料費仍按普通研究一次原子支付，傳承只縮短秒數。批量加工仍有原 Era4、採石場、工坊、祖島支付與單批容量限制，既有工作 remaining 不重算。輪迴重置沿 B：當世完成／在製研究與設備清空。

## 範圍與驗證

D1 最遠 Era4 Lv10，突破 Era5、古藥／太虛與後段配方仍具名拒絕，不能宣稱已交付完整 D。

`econ_r1_deep_runner.gd` 預設只跑短契約；`DAO_ECON_D_EARNED=1` 明確執行從空白 profile 起的長分析。只有專門標示的 unit fixture 注入狀態，它們用獨立 GameSession／MemoryAdapter，從不回填賺得路徑。賺得路徑沿 C 合法命令與權威秒數到 Era3，再研究 R08、突破元嬰、開寒銀並依序研究，最後實付元嬰九次升層。報告保留所有命令、研究與建築付款容量、等待分類、末態指紋；測試存檔只在 `.test-output/`。

這是加速規則模擬；沒有自然時間 Chrome 滑鼠、五宗長線或80–160小時平衡結論。UI 在 E；候選包／大型 L3 在 F。
